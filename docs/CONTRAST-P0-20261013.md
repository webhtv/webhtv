## 1. 缺陷一：手机端「追更」卡片的硬编码固定色

### 1.1 证据

`mobile/res/layout/item_following.xml` 有两处写死的调色板色值，而 `main` 源集的同名文件在**同一位置**用的是语义属性——即手机端独有的偏离：

| 位置 | mobile（改动前） | main |
|---|---|---|
| L73「新 N 集」角标 | `#174EA6` | `?attr/colorPrimary` |
| L124「检查失败」 | `#B3261E` | `?attr/colorError` |

底材是语义 token（角标走 `shape_sync_direction` = `?attr/colorSurfaceContainer`，**随主题变**），文字却不跟：

| 位置 | 浅色底 `#E7E8EF` | 深色底 `#2A2F34` | 门槛 |
|---|---|---|---|
| `#174EA6` | 6.42:1 ✓ | **1.72:1** ✗ | 4.5:1 |
| `#B3261E` | 5.35:1 ✓ | **2.07:1** ✗ | 4.5:1 |

`#B3261E` 正是**浅色表的 M3 错误红**，而它承载的文字是「检查失败」——§9.9 管辖的错误态。

### 1.2 修法

两处都改为与 `main` 一致的语义属性（`?attr/colorPrimary` / `?attr/colorError`）。这是**对齐既有正确实现**，不是新设计。

## 2. 缺陷二：空态/错误态描述文字直接压在壁纸上

### 2.1 关键：这不是"差一点"，而是**物理上不可达**

描述文字用 `?attr/webhtvColorOnWallpaperVariant` = `#CCFFFFFF`（80% 白），16sp 正文，门槛 4.5:1。壁纸实机取样合成亮度 L=0.1217/0.1476/0.2019：

| 前景 | 最暗壁纸 | 平均壁纸 | 最亮壁纸 |
|---|---|---|---|
| 80% 白（现状） | 4.61:1 ✓ | **4.08:1** ✗ | **3.30:1** ✗ |
| 90% 白 | 5.33:1 | 4.67:1 | 3.72:1 ✗ |
| **100% 纯白** | 6.12:1 | 5.31:1 | **4.17:1** ✗ |

**即使换成纯白，最亮壁纸上限也只有 4.17:1**——4.5:1 物理上不可达。所以"调亮前景色"这条路是死的，必须改**底材**。这与 TV-6 对"取值文字"的处理完全同类。

### 2.2 更根本的问题：它违反 §5.3 / §5.4

- §5.3：「**图片上的文字必须有 scrim/gradient**；不得假设海报亮度足够。」
- §5.4：「原始壁纸视觉可作为页面 canvas 的底图，但**所有内容表面必须有不透明或可控的 surface 层**。」

而空态/错误态的文字**直接压在壁纸（一张图）上、没有任何 scrim**。所以这不只是对比度差一点，而是**违反这两条明文要求**。

### 2.3 修法：加 scrim，而不是加实心底

算过需要多强：

| scrim（黑） | 最暗 | 平均 | 最亮 | |
|---|---|---|---|---|
| 0% | 4.61 | 4.08 | 3.30 | ✗ |
| 15% | 5.63 | 5.05 | 4.17 | ✗ |
| **20%** | 6.02 | 5.43 | **4.53** | ✓ 全部达标 |
| 25% | 6.44 | 5.85 | 4.92 | ✓ |
| 32%（`overlay_dark`） | 7.0+ | 6.4+ | 5.4+ | ✓ 更宽裕 |

**20% 就够**，且**不需要改文字色**。仓库已有 `webhtv_color_overlay_dark` = `#52000000`（≈32% 黑）——正好够用，而且它正是审计发现的"只声明、从未赋值"的三个属性之一。

**为什么加 scrim 而不是像 TV-6 那样加实心底**：空态在电视端是**居中大段文字 + 插画 + 按钮**，加实心小底会很难看；scrim 盖的是整屏，观感是"页面暗下来"，符合"内容之上的浮层"语义。

### 2.4 加在哪一层

加在 **`ProgressLayout` 自身**，不是 `view_empty.xml` 的内容块：

- 空态视图是**居中摆放的 `wrap_content` 内容块**（`centerParams()` 用 `CENTER_IN_PARENT`），给它加背景会变成"文字后面一块小方框"；
- `ProgressLayout` 是 `match_parent` 的宿主层，盖的是整屏。

且**只在 EMPTY/ERROR 态**加，其余状态 `setBackground(null)` 清掉——否则会盖住正常内容。**PROGRESS 态刻意不加**：它是短暂的加载瞬间，加 scrim 会让页面闪一下暗。

## 3. 实施

1. `mobile/res/layout/item_following.xml`：两处 `textColor` 改为 `?attr/colorPrimary` / `?attr/colorError`。
2. `webhtv_styles.xml` 的 `Theme.WebHTV`：给 `webhtvColorOverlayDark` 赋 `@color/webhtv_color_overlay_dark`（此前只声明、从未赋值），并写明为什么需要它。
3. `ProgressLayout`：新增 `applyScrim(State)`，在 `switchState` 里调用——EMPTY/ERROR 设 scrim，其余清空。
4. 新增两个契约测试：
   - `MobileFollowingCardSemanticContractTest`（3 项）：两处对齐语义角色；**该布局里不应再有任何写死的 `textColor`**；两端同名布局必须用同一套角色。
   - `StateSurfaceScrimContractTest`（4 项）：EMPTY/ERROR 必须带 scrim；**PROGRESS/CONTENT 刻意不带**（边界守卫）；`webhtvColorOverlayDark` 必须真的接线（只声明不接线等于没有）；描述文字必须仍是 16sp 正文（scrim 的对比度按正文门槛核算）。

### 5.3 结论

两处对比度缺陷都已修复：手机端追更卡片的两处硬编码色对齐到 `main` 的语义角色（深色底由 1.72/2.07:1 变为跟随主题）；空态/错误态浮层加了 scrim，把"文字直接压在壁纸上"这一**违反 §5.3/§5.4** 的做法改掉，实测三种壁纸下全部达标（6.02/5.43/4.53:1）。

### 5.4 残余风险与诚实说明

- **手机端追更卡片的修复未在真机确认**：需要「追更」列表里有数据且处于深色主题才能看出差异。该修复是**对齐 `main` 的既有正确实现**（同位置、同属性），由契约测试覆盖。
- **未在浅色主题下实测 scrim**：scrim 是按最亮壁纸（最坏情况）核算的，浅色主题下壁纸更亮则收益更大。
- **错误态（ERROR）的 scrim 未单独截图**：它与 EMPTY 走同一个 `applyScrim` 分支，且 `StateSurfaceScrimContractTest` 断言两者都覆盖。
- **scrim 的观感是"整页暗下来"**：这是刻意的取舍（见 §2.3），但**是否好看**属主观判断，我只验证了它生效且对比度达标。
