## 1. 三项决策与理由

用户授权"按你推荐的方案来"。我的推荐原则是：**规范自由的地方采用规范；规范没考虑到已记录技术约束的地方，把规范写精确**——而不是让规范去描述现状。

| # | 决策 | 我的推荐 | 理由 |
|---|---|---|---|
| ① | 内容卡圆角 8dp vs 规范 12dp | **保留 8dp，把理由写进规范**；但**输入框 4dp → 8dp 采用规范** | 见 §1.1 |
| ② | 播放器错误层要不要"错误色" | **不加**，在规范里写成**明文例外** | 见 §1.2 |
| ③ | 手机分类/筛选面板用播放控制玻璃 | **保留**，把规范规则**收窄到真实判据** | 见 §1.3 |

### 1.1 为什么卡片保留 8dp 而输入框改 8dp——两者性质不同

核对规范 §7.1 与既有契约后发现，**网格内容卡的 8dp 不是"随手的现状"，而是与焦点环几何耦合的取舍**。契约注释原文：

> 环的**外边界**圆角半径 = 声明值 + w/2。声明 8dp 时外边界为 8dp + w/2 > 8dp，比卡片自身的弧更大，沿角落对角线卡片弧反而更靠外，露出 1–2px 月牙。

所以改卡片半径必须**同步重算环几何并重验月牙**——有真实代价，且 `TvFocusRingContractTest` 已把 8dp 固化为契约。

而**输入框的 4dp 没有这个耦合**：它属 §7.1 里"标签、微小 chip"的 `shapeExtraSmall` 档，被放在小一档的位置上，是**纯粹偏离**。所以：

- 卡片：保留 8dp，**把理由写进 §7.1**（否则下一个人会"顺手"改成 12dp 并撞上月牙）；
- 输入框：**按规范改为 8dp**（`selector_dialog_input.xml` 两处同步）。

### 1.2 为什么播放器错误层不加错误色

§9.9 要求"错误色 + 原因 + 重试动作"。这条在**应用表面**上成立且已落地（`?attr/webhtvColorOnWallpaperError` + 实心深底 `shape_error_value`，实测 8.84:1）。

但播放器错误层画在 `shape_widget`（50% 黑）之上，下面叠的是**任意视频画面**——底材不可控，任何带色相的前景色都给不出对比度保证。要让它也满足"错误色"，就得给它一块不透明实心底，那会改变播放页观感。

**决定：不加。** 播放器错误层的契约是"错误文案 + 重试动作"（两者均已落地），颜色沿用播放器层 token（白）。**把这条写进 §9.9 作为明文例外**——否则下一个人会去"补"错误色并降低对比度。

### 1.3 为什么玻璃判据要收窄

§7.2 原文把玻璃限定在"播放器、图片叠加或明确的沉浸场景"。审计曾把手机端分类/筛选面板（`dialog_type.xml`、`dialog_filter.xml`）记为"越界"。

复核后判定**不应按越界处理**，因为**原判据过窄**：玻璃真正的风险不是"出现在哪个页面"，而是**透明度成为可读性的唯一保障**——§5.3 已明文如此要求。分类/筛选面板是内容之上的浮层，其下是应用自身可控的浏览页表面，并且**确实带了 scrim**，因此满足 §5.3。

真正需要禁止的是：玻璃**直接压在不可控底材上**（任意视频画面、任意海报、用户壁纸）且没有 scrim——播放器控制层属此类，所以它有专门的 `?attr/tvPlayerRing` 环族与 `player_control*` token 族。

**判据（替代"仅播放器"）**：一个面板可以用玻璃，当且仅当 ①其底材是应用可控的表面，或 ②它在其上叠加了足够不透明的 scrim。

## 2. 实施

1. `selector_dialog_input.xml`：两处 `android:radius` 由 4dp 改为 8dp，并注明依据（§7.1 `shapeSmall`）与"两处必须同步，否则聚焦时圆角会跳一下"。
2. 规范 §7.1：新增补充段，记录网格内容卡 8dp 的**理由**（环外边界半径 = 卡片半径 + 环宽/2 → 月牙）、四步修改流程（改半径 → 重算环几何 → 重验月牙 → 同步契约），并点明输入框那处偏离已按本表修正。
3. 规范 §7.2：新增补充段，把玻璃判据从"宿主是不是播放器"收窄为"底材是否可控 / 是否有 scrim"。
4. 规范 §9.9：新增例外段，记录播放器错误层不用错误色的理由，并说明 OSD 白字与 `PlayerOsdController` 的 `0xFFFFFFFF` 同属此类、不计为偏离。
5. 新增 `DialogInputCornerContractTest`（5 项）：输入框两处都是 8dp 且不再有 4dp；底材保持语义、无写死色；§7.1/§7.2/§9.9 的三段理由**必须留在规范里**（防止被后续"顺手清理"删掉）。

### 4.3 结论

三项决策落地：输入框圆角按 §7.1 修正为 `shapeSmall` 8dp（两处同步）；网格内容卡 8dp 的**理由**写入 §7.1（含四步修改流程，防止后续被"顺手"改成 12dp 而撞上月牙）；§7.2 的玻璃判据由"宿主是不是播放器"收窄为"底材是否可控 / 是否有 scrim"；§9.9 记录播放器错误层为明文例外。

### 4.4 残余风险与诚实说明

- **只验证了输入框这一处视觉改动**：另两项是规范文本与判据的修订，不改实现，因此没有可观测的界面变化——它们的"验证"就是契约测试对规范文本的断言（防止理由被删）。
- **未验证聚焦态的实际渲染**：我截到的是常态；聚焦态圆角由同一文件同一数值保证（契约测试断言两处都是 8dp）。
- **§7.2 的新判据未逐面板复核**：本批只改判据文字，未重新审计所有玻璃面板是否都满足"底材可控或有 scrim"。审计已记录分类/筛选面板**确实带了 scrim**，其余面板未逐一复核。
