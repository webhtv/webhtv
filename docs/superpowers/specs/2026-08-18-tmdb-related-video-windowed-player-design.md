# TMDB 相关视频窗口化原生播放器设计

## 状态

已获用户确认，待实施。

本文取代 2026-08-17-tmdb-related-video-fullscreen-design.md 中 点击相关视频后立即进入临时全屏 Activity的交互方案；TMDB 视频发现、筛选、排序、卡片展示等既有设计保持不变。

## 背景

当前相关视频卡片通过 TmdbVideoPlayback 启动 TransientVideoActivity，随后进入完整的 VideoActivity 播放页。这条链路会先显示一个与内容无关的中间界面，再切入全屏播放器，造成明显的页面跳转和上下文丢失。虽然当前解析链路已能隔离主播放器状态，但交互仍不符合先预览、再由用户决定是否全屏的预期。

项目此前存在 TmdbVideoPlayerDialog：它在详情页上方打开独立的 Media3 播放窗口。用户希望保留当前相关视频卡片选择方式，同时恢复这种窗口化交互，并在弹窗内提供主动全屏入口。

用户口中的之前的窗口化 HTML 效果在本方案中指窗口化视觉与交互，不恢复真实 WebView/iframe 播放。播放器继续使用原生 Media3，以避免网页广告、Cookie、遥控器焦点、编解码和全屏 API 兼容问题。

## 目标

- 保留当前 TMDB 相关视频卡片、筛选和选中逻辑。
- 点击卡片后直接在当前详情页上方打开窗口化播放器，不进入中间 Activity。
- 弹窗打开后播放用户刚刚选择的那一条相关视频。
- 相关视频解析使用隔离接口，不覆盖正片的全局播放源和状态。
- 弹窗提供播放/暂停、进度拖动、关闭和全屏按钮。
- 全屏与窗口模式共用同一个播放器实例、同一媒体源和同一播放位置。
- 返回键行为可预测：全屏时先退回窗口，窗口时再关闭弹窗。
- 关闭弹窗后恢复详情页、原正片状态和相关视频卡片焦点。
- 手机版与 Leanback 版保持一致的核心行为，并分别适配触摸和遥控器焦点。

## 非目标

- 不在弹窗中复刻正片播放页的全部能力，例如选集、字幕管理、音轨切换、弹幕、片头片尾和播放参数面板。
- 不使用 WebView、YouTube iframe 或外部浏览器作为主要播放链路。
- 不把相关视频写入正片播放历史，也不改变当前影片的集数和续播位置。
- 不为了弹窗全屏继续保留第二套临时 Activity 跳转链路。
- 不修改 TMDB 视频发现、语言优先级、排序和卡片数据模型。

## 推荐方案

### 总体结构

相关视频点击链路调整为：

1. TmdbVideoAdapter 或 TmdbVideoPresenter 把用户选中的 TmdbVideo 交给 TmdbVideoPlayback.play(...)。
2. TmdbVideoPlayback.create(...) 继续完成 URL、标题、封面和播放标记标准化。
3. TmdbVideoPlayback.play(...) 不再创建 TransientVideoActivity Intent，而是调用 TmdbVideoPlayerDialog.show(...)。
4. 弹窗立即出现并展示加载态，后台通过 SiteApi.playerContentIsolated(...) 解析相关视频。
5. 解析成功后把结果交给弹窗专属 Media3 播放器；解析失败时在弹窗内显示错误，不跳转到其他页面。

弹窗播放器必须与详情页正片播放器隔离。它不能调用会覆盖全局 Source、正片集数或播放历史的普通解析入口，也不能通过启动完整 VideoActivity 来获得全屏效果。

### 窗口模式

- 弹窗居中覆盖在当前详情页上方，背景保留可见并使用遮罩弱化。
- 播放区域保持 16:9；手机和平板按可用宽高限制最大尺寸，电视端采用更大的居中窗口，但仍能看出详情页上下文。
- 顶部显示相关视频标题和关闭按钮；底部使用原生 Media3 控制条或等价的精简控制条。
- 打开后自动开始解析和播放，加载期间显示明确的进度状态。
- 点击遮罩不直接关闭，避免触摸误操作；关闭按钮和返回键负责退出。
- Leanback 初始焦点优先落在播放区域或播放/暂停控件，关闭与全屏按钮必须可通过方向键稳定到达。

### 全屏模式

全屏不创建新的 Activity，也不创建第二个播放器。弹窗只改变自身窗口和容器布局：

- 窗口模式使用居中的有限尺寸容器。
- 点击全屏后，同一个 Dialog Window 扩展到 MATCH_PARENT，同一个 PlayerView 扩展到全屏容器。
- 保留同一播放器实例、媒体源、缓冲数据、播放/暂停状态和当前位置，不重新调用解析接口。
- 全屏时进入沉浸式显示，并按现有平台约定处理系统栏；退出全屏时恢复原窗口尺寸和系统 UI。
- 手机端如需切换横屏，只在进入全屏时请求，并在退出或关闭时恢复宿主原方向；电视端保持现有横向布局。
- 全屏状态下按返回键只退出全屏；再次按返回键才关闭窗口。

优先通过修改 Dialog Window 的 LayoutParams 和根容器样式完成放大，避免不必要的 View 重建或跨窗口 reparent。若布局约束要求移动 PlayerView，也必须移动同一个 View 和播放器实例，而不是重新创建播放器。

### 正片暂停与恢复

弹窗打开前记录宿主正片是否正在播放：

- 若正片正在播放，弹窗进入有效显示状态后暂停正片，防止双重音频。
- 若正片本来已暂停，关闭弹窗后仍保持暂停。
- 弹窗正常关闭时先停止并释放自己的播放器，再仅在宿主仍存活且打开前正片正在播放时恢复正片。
- 宿主 Activity 销毁、切换影片或进程回收时，弹窗取消未完成解析并释放资源，不尝试恢复已经失效的宿主。
- 弹窗播放不得改写宿主正片的播放位置、播放源、集数、历史记录或服务绑定状态。

若现有 PlaybackActivity 没有足够窄的暂停/恢复接口，新增只服务于覆盖式子播放器的最小接口；不复用临时全屏快照来模拟弹窗生命周期。

### 焦点与输入

- 打开弹窗前记录触发卡片或相关视频列表的焦点位置。
- 关闭弹窗后优先恢复到原卡片；原卡片不存在时恢复到相关视频区域的最近可用项。
- 遥控器返回键顺序为：隐藏已展开控制面板（如适用）→ 退出全屏 → 关闭弹窗。
- 触摸端单击播放区域显示或隐藏控制条；遥控器确认键遵循 Media3 控制条行为。
- 连续点击不同卡片时不允许叠加多个弹窗。已有弹窗时应关闭并释放旧实例后打开新选择，或让现有弹窗切换到新选择；首版采用关闭旧实例后打开新选择，以保持状态机简单。

## 播放与异步生命周期

### 隔离解析

相关视频必须调用 SiteApi.playerContentIsolated(...)，参数沿用 TmdbVideoPlayback.Launch 中的 PUSH key、播放标记、名称和 URL。禁止调用会修改全局播放源的 SiteApi.playerContent(...)。

解析结果由弹窗自己的生命周期令牌或 generation 校验：

- 弹窗已关闭或宿主已销毁时，迟到的解析结果直接丢弃。
- 新视频替换旧视频后，旧请求结果不能覆盖新选择。
- 解析任务、播放器监听器和 UI 回调都在 dismiss/onDestroyView 中解除。

### 错误处理

- 视频对象、播放 URL 或宿主无效：TmdbVideoPlayback.play(...) 返回 alse，不打开空弹窗。
- 解析失败：保留弹窗并显示简短错误和关闭按钮；首版不自动回退到浏览器或临时全屏 Activity。
- 播放器加载失败：在播放器区域显示错误，允许关闭；重试按钮仅在现有通用组件可低成本复用时加入。
- 全屏切换失败：保留当前窗口播放，不中断媒体流。
- 正片恢复失败：只记录日志，不重新创建宿主或写入错误播放状态。

## 迁移与清理边界

实现时先确认临时播放设施是否还有其他调用方。若只服务于 TMDB 相关视频，则删除以下功能专用链路：

- Mobile/Leanback TransientVideoActivity 及 Manifest 注册。
- TransientPlaybackCoordinator、TransientPlaybackSnapshot 及其仅用于该链路的测试。
- PlaybackActivity.launchTransientPlayback(...) 和只服务于临时相关视频的快照/恢复逻辑。
- Mobile/Leanback VideoActivity 中的 EXTRA_TRANSIENT_PLAYBACK 分支和仅为该模式增加的选集绕过逻辑。

若确认某个组件存在独立调用方，则保留该组件，但相关视频入口仍必须改走弹窗。清理时保留与本交互无关的通用播放服务释放策略和 VodEventGuard 等既有修复。

已有未提交的临时播放修正如在新方案中失去调用场景，应在实施提交中明确移除或还原，而不是留下不可达分支。

## 测试策略

### 自动化测试

至少覆盖：

1. TmdbVideoPlayback.create(...) 仍正确标准化标题、URL、标记和 PUSH 请求。
2. TmdbVideoPlayback.play(...) 打开 TmdbVideoPlayerDialog，不再启动 TransientVideoActivity。
3. 弹窗解析使用 playerContentIsolated(...)，不存在普通全局解析入口。
4. 窗口/全屏切换不重新创建播放器、不重新解析、不重置播放位置。
5. 全屏返回键先恢复窗口，窗口返回键再关闭。
6. 正片仅在打开前处于播放状态时恢复。
7. 弹窗关闭、宿主销毁或选择变化后，迟到解析结果不会更新 UI。
8. 连续选择相关视频不会产生多个同时播放的播放器。
9. Mobile 与 Leanback 布局均包含可达的关闭、播放和全屏控件，Leanback 焦点顺序稳定。
10. 若临时播放链路被删除，代码与 Manifest 中不再残留相关入口；若保留，相关视频入口也不能引用它。

### 设备验收

在手机模拟器与 Leanback 设备上分别验证：

1. 进入影片详情，选择任意相关视频卡片。
2. 当前详情页上立即出现窗口化播放器，不出现星空/空白中间页。
3. 播放内容、标题、时长与选中的相关视频一致，画面和声音均正常。
4. 正片音频在弹窗播放期间停止，且正片位置不被相关视频覆盖。
5. 点击全屏后画面连续、播放位置不归零、不会重新出现加载页面。
6. 全屏按返回键回到同一窗口，播放位置继续；再次返回关闭弹窗。
7. 关闭后回到原相关视频卡片，正片按打开前状态恢复。
8. 解析失败、断网、快速关闭和连续切换卡片时不崩溃、不串音、不出现错误视频。

## 备选方案与取舍

1. **窗口播放，点击全屏后进入 VideoActivity**：可以复用完整控制页，但仍会发生 Activity 跳转、重新解析和位置衔接问题，不满足同一个播放器自然放大的体验。
2. **真实 WebView/iframe 窗口**：视觉接近网页，但引入广告、Cookie、地区限制、遥控器焦点、网页全屏和硬件解码差异，稳定性低于现有原生解析链路。
3. **保留当前自动临时全屏**：实现已存在，但用户已明确拒绝中间页和自动全屏交互。
4. **窗口化原生播放器 + 同实例全屏（本方案）**：最大限度恢复旧交互，同时保留当前卡片选择和隔离解析，改动范围可控，是推荐方案。
