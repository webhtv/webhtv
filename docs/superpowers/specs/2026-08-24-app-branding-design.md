# APP 名称与图标自定义设计

## 目标

在个性设置中允许用户修改 APP 名称，并在“当前图标、历史图标、自定义图标”三种方案中选择。当前/历史图标需要能切换系统桌面入口；自定义图片使用系统桌面快捷方式承载，因为 Android 安装包的 `application` 图标和 `activity-alias` 图标只能引用静态资源，不能在运行时指向用户文件。

## 方案

- 在 TV 与手机的个性设置中增加同一个“APP 名称与图标”入口，跳转到主 source set 的通用编辑页，避免两套产品形态出现不同的持久化逻辑。
- 用 `AppBranding` 作为唯一数据/应用边界：名称写入默认 `SharedPreferences`，图标模式写入整数，用户图片复制为应用私有目录中的标准 PNG；不保存外部 URI。
- 在 TV/mobile manifest 中把 `HomeActivity` 的桌面入口改为两个 `activity-alias`：当前图标 alias 默认启用，历史图标 alias 默认停用。保存内置图标时用 `PackageManager` 切换 alias，并保留 `HomeActivity` 作为实际目标以兼容搜索、分享和视频打开等已有入口。
- 自定义图片保存成功后调用 `ShortcutManagerCompat.requestPinShortcut`，快捷方式使用用户名称和私有 PNG；默认入口保留为当前图标，避免用户拒绝桌面添加请求后失去启动入口。TV 设备不支持固定快捷方式时显示明确提示，但仍保存名称与图片供应用内使用。
- 应用内标题、首页名称、通知标题等直接显示应用名的动态位置改用 `AppBranding.getName()`；未设置名称时继续使用现有本地化 `app_name`。

## 输入与错误处理

- 名称去首尾空白，限制为 1–32 个 Unicode 字符；空值表示恢复系统默认名称。
- 自定义图片只接受 `image/*`，读取时限制输入大小 5 MiB、尺寸 4096×4096，解码后缩放到不超过 512×512 并写入临时文件，成功后原子替换目标文件。
- 文件选择、解码、写入或桌面快捷方式请求失败时保留上一次有效配置，并通过现有 `Notify` 反馈，不把路径或异常堆栈展示给用户。
- 自定义图标文件缺失或损坏时自动回退到当前内置图标。

## 验证

- JVM/source tests 覆盖名称清理、图标模式回退、组件 alias 选择和自定义图标边界。
- 分别编译 mobile 与 leanback debug 变体，检查 manifest 合并、资源解析和 ViewBinding。
- 手动验证首次安装、当前/历史切换、名称修改、自定义图片取消/非法图片/大文件、重启后配置保留，以及系统桌面确认快捷方式后的启动行为。
