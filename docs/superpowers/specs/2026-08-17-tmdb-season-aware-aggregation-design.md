# TMDB 电视剧季度感知聚合设计

## 状态

- 日期：2026-08-17
- 状态：方案已原则确认，等待书面规格复核
- 关联文档：`docs/tmdb-season-manual-match-design.md`

## 背景

同一部 TMDB 电视剧的不同季度共享 `mediaType + tmdbId`。当前标题归一化和历史展示聚合主要使用这一节目级身份，因此以下来源条目可能被压成同一条记录：

- `乐高幻影忍者：神龙崛起`
- `乐高幻影忍者：神龙崛起第二季`
- `乐高幻影忍者：神龙崛起第三季`

这不是某一部作品的特例。中文“第 N 季”、英文 `Season N`、`S02`，以及一个播放线路连续包含多个季度时，都可能触发相同问题。现有实现已经具备季度解析、手动匹配和多季度切片能力，但季度身份还没有完整传递到标题、历史投影、续播和线路切换。

主要风险点如下：

- `TmdbUIAdapter.applyTmdbTitle` 会把来源中的明确季度标题替换为 TMDB 节目标题。
- `HistoryDisplayPolicy` 仅按 `mediaType + tmdbId` 聚合时，不同季度会合并。
- `HistorySourceResolver` 若只比较节目身份，可能把续播线路切换到另一季度。
- `History` 以来源键保存一份最近进度；一个来源线路同时包含第一、二季时，无法保留两季各自的最近进度。
- 删除历史若按节目身份级联，会连带删除同一节目的其他季度。

## 决策

采用“节目级详情页 + 季度级历史和续播 + 不确定项隔离”的混合方案。

1. 同一 TMDB 电视剧继续共用一个详情页。
2. 历史卡片、续播进度、自动换源和删除均以已确认季度为边界。
3. 一个线路可绑定一个季度或多个有明确切片边界的季度，并向对应季度提供播放线路。
4. 无法可靠确认季度时，记录保持来源隔离，不参与跨来源自动聚合或自动续播。
5. 不再通过覆盖来源标题来表达 TMDB 归一化结果；来源标题、TMDB 标题和界面标题分别建模。

该方案对应“多个季度共用详情页，但每季独立记录进度并汇总可用线路”，同时增加 UNKNOWN 安全边界，避免错误合并比重复展示造成更严重的数据错乱。

## 目标

- 不同季度不再因为 TMDB ID 相同而合并为一条历史。
- 第一季和第二季合集源可以同时服务两个季度，第三季独立源只服务第三季。
- 同一节目各季保留独立最近播放集数和播放位置。
- 用户进入节目详情页后，可以按季度看到该季所有可用来源线路。
- 已确认季度之间允许可靠换源；季度不明时不进行跨来源自动换源。
- 兼容现有 `History.key`、已有手动季度匹配和旧历史数据。

## 非目标

- 不改变 TMDB 自身的节目、季度和剧集数据模型。
- 不通过标题相似度强行猜测季度。
- 不一次性重写全部历史存储或播放器流程。
- 不把电影引入季度模型；电影仍使用节目级身份。
- 不自动删除或不可逆迁移无法确认季度的旧记录。

## 身份模型

### 节目身份

```text
MediaIdentity = mediaType + tmdbId
```

用途：详情页、TMDB 元数据、同一作品判断。电视剧不同季度共享该身份。

### 季度身份

```text
SeasonIdentity = MediaIdentity + KnownSeasonNumber
```

用途：历史展示、续播、进度、删除边界和换源候选。

季度必须使用显式状态表示，不能仅依赖整数默认值：

```text
SeasonScope = Known(seasonNumber)
            | Multi(segments)
            | Unknown
```

- `Known(0)` 仅表示已经明确映射到 TMDB 特别篇。
- `Unknown` 表示没有足够证据确认季度。
- `Multi` 表示一个线路覆盖多个季度，并且每一季都有可验证的剧集切片边界。
- 原始整数 `0` 不得同时承担“特别篇”和“未解析”的含义。

### 来源线路绑定

```text
SourceBindingKey = siteKey + vodId + flagKey
SourceBinding    = SourceBindingKey + SeasonScope + evidence
```

绑定粒度必须下沉到播放线路 `Flag`。同一个来源详情可能有“第一季”“第二季”“全集”等不同线路，只给整个 `Vod` 保存一个季度会丢失线路差异。

`flagKey` 应使用来源内稳定标识。若来源没有独立 ID，则使用能在同一详情内稳定复现的线路值与序号组合，不能只使用可变的界面显示名。

`Multi` 的每个分段至少包含：

```text
SeasonSegment = seasonNumber
              + sourceEpisodeStartIndex
              + sourceEpisodeEndIndex
              + tmdbEpisodeStartNumber
```

只有知道分段边界，才能把播放位置和某一季的 TMDB 剧集准确对应。

## 季度解析规则

季度证据优先级如下：

1. 用户手动绑定。
2. 明确的请求上下文或已经保存的可靠绑定。
3. 来源标题、线路标题或剧集键中的明确季度标记。
4. 单季度唯一候选。
5. 来源剧集数与 TMDB 某季度精确匹配。
6. 扁平剧集序号与多个季度的完整集数切片精确匹配。
7. 无法唯一证明时为 `Unknown`。

后一级证据不得覆盖前一级证据。自动解析只能在结果唯一时落盘；多个候选季度同样合理时进入手动匹配，而不是默认第一季。

### 多季度合集判定

一个扁平线路只有满足以下任一条件时才可绑定为 `Multi`：

- 剧集本身带有明确的季、集标记，可逐集映射；或
- 来源剧集序号完整、连续，且 TMDB 各季集数的组合能唯一且完整地覆盖来源列表。

例如来源 A 恰好包含第一季和第二季全部剧集，来源 B 明确为第三季：

- A 保存为 `Multi([S1 segment, S2 segment])`，分别出现在第一季和第二季的线路列表中。
- B 保存为 `Known(3)`，只出现在第三季线路列表中。
- A 中播放到第二季时，写入第二季进度，不覆盖第一季进度。

若集数缺失、重排或多种切片都成立，则 A 保持 `Unknown` 并提示手动绑定。

## 标题模型

标题分为三个概念：

```text
sourceTitle    = 来源原始标题
canonicalTitle = TMDB 节目标题
displayTitle   = 当前界面按上下文生成的标题
```

规则如下：

- `sourceTitle` 必须在应用 TMDB 元数据前保存，不能被不可逆覆盖。
- 来源标题已经明确包含季度时，兼容阶段的 `Vod.name` 保留原始来源标题。
- 节目详情页主标题使用 `canonicalTitle`，季度通过季度选择器表达。
- 历史卡片在季度已知时显示节目标题和季度标签；若当前模型还没有独立的 `displayTitle` 字段，可先保留含季度的来源标题。
- 季度未知时不伪造“第一季”等标签。
- 电影和没有季度语义的内容继续使用 TMDB 标题归一化。

标题只负责展示，不能作为已确认季度身份的替代品。标题解析结果必须经过季度解析器验证后才能参与聚合。

## 历史投影与聚合

电视剧历史展示键定义为：

```text
Known season: mediaType:tmdbId:season:seasonNumber
Unknown:      source:History.key
Movie:        mediaType:tmdbId
```

因此：

- 同一 TMDB 节目的第一季与第三季生成两张历史卡片。
- 同一季度的多个来源可投影为同一张季度卡片。
- 未确认季度的记录按来源键保持独立，不能仅按 TMDB ID 合并。
- 多季度线路的历史归属由“实际播放剧集对应的季度”决定，不以线路覆盖的全部季度生成重复历史。

季度卡片选择更新时间最新的记录作为展示代表，但需要保留该季度内所有可用来源，供详情页和换源使用。

## 进度模型

保留现有 `History` 作为来源路由和兼容记录，`History.key` 不改变。新增季度级续播快照，用于解决一个来源覆盖多个季度时只有一份最近进度的问题。

```text
TmdbSeasonProgressKey = mediaType + tmdbId + seasonNumber
TmdbSeasonProgress    = latestTmdbEpisodeNumber
                      + playbackPosition
                      + duration
                      + lastSourceHistoryKey
                      + lastSourceBindingKey
                      + updatedAt
```

写入规则：

- 只有 `Known` 季度或已定位到 `Multi` 某一分段的实际剧集才写季度进度。
- 第一季第 5 集和第二季第 5 集是两个不同进度。
- 播放另一季度不会覆盖当前季度快照。
- `Unknown` 只更新来源自己的 `History`，不写 TMDB 季度进度。
- 季度快照保存最近可恢复位置；现有来源历史继续承担具体播放地址、线路和兼容字段。

读取规则：

1. 先以 `SeasonIdentity` 查季度进度。
2. 再尝试恢复其最后来源线路。
3. 最后在同季度兼容线路中选择可播放候选。
4. 原线路已失效且没有同季度候选时，停留在选源界面，不跨季回退。

数据库变更采用新增表或等价的加法式结构，不破坏现有 `History` 表主键和已有字段。旧记录按需解析并渐进回填；不能确认季度的旧记录保持原状。

## 共用详情页

详情页仍以 `MediaIdentity` 打开，内部状态以当前季度组织：

```text
TMDB 节目详情
  -> 季度选择
  -> 当前季度可播放剧集
  -> 当前季度可用来源线路
  -> 当前季度续播位置
```

线路可用性规则：

- `Known(N)` 线路只属于第 N 季。
- `Multi` 线路属于其分段声明的每个季度，切换季度后使用对应分段。
- `Unknown` 线路显示在“待匹配/原始来源”区域，不自动混入任何已知季度。
- 用户完成手动绑定后，详情页立即按新绑定刷新线路归属。

详情页共用不等于进度共用。季度切换必须同步切换剧集列表、线路候选和续播快照。

## 自动换源与续播

候选线路必须先通过季度兼容判断，再参与标题、年份、清晰度或更新时间评分：

```text
target Known(N) accepts source Known(N)
target Known(N) accepts source Multi containing N
target Known(N) rejects source Known(M), where M != N
target Known(N) rejects source Unknown for automatic switching
target Unknown only resumes its original source automatically
```

手动选择未知线路是用户明确行为，可以进入匹配流程；它不能被系统当作同季度可靠候选保存，直到季度得到确认。

## 删除语义

删除操作必须与界面对象边界一致：

- 删除某一季度历史：删除该季度进度，并删除或解除仅属于该季度的历史投影；不得删除同一 TMDB 节目的其他季度进度。
- 删除未知季度历史：只删除该来源记录。
- 删除整部节目历史：作为独立、明确的二级操作，删除该 `MediaIdentity` 下所有季度进度和关联来源历史。
- 多季度线路中删除第一季历史时，只清除第一季快照；第二季快照仍保留。来源路由记录仅在其当前快照属于被删除季度且不再被其他季度引用时删除。

现有按 TMDB 节目身份自动级联删除的行为需要收窄，不能继续作为季度卡片的默认删除语义。

## 异常与降级

- TMDB 请求失败：保留来源标题、来源历史和原线路，不改变已保存绑定。
- 季度解析冲突：标记为 `Unknown` 或进入手动匹配，不覆盖旧的高置信度绑定。
- 来源线路结构变化：原绑定校验失败后失效，重新解析；旧季度进度保留。
- TMDB 季度集数后续变化：只有重新验证通过后才更新 `Multi` 分段，避免静默错位。
- 旧数据季度字段为默认 `0`：除非有特别篇证据，否则按未知处理。

这些降级路径的共同原则是：可以暂时重复展示，但不能跨季度恢复错误进度。

## 兼容与迁移

迁移采用惰性、可回退策略：

1. 读取旧历史时，用现有季度解析器检查标题、已保存季度和剧集映射。
2. 只有结果唯一时生成季度投影或季度进度快照。
3. 无法确认的记录继续以来源键展示。
4. 新写入同时维护来源 `History` 和已确认的季度进度。
5. 稳定版本运行一段时间后，仍不删除旧字段或旧记录。

已有 Vod 级手动绑定继续读取。只有详情中存在唯一线路，或旧绑定能唯一映射到某一线路时，才自动升级到 Flag 级绑定；否则要求用户重新确认，防止把一个季度绑定错误应用到所有线路。

## 实施阶段

### 阶段一：阻止当前错误合并

- 保留明确含季度的来源标题。
- 历史投影改为季度键。
- 未知季度改为来源隔离键。
- 删除和自动换源增加严格季度边界。
- 覆盖当前复现案例和主要回归测试。

### 阶段二：线路级绑定与独立进度

- 将季度绑定从 Vod 粒度扩展到 Flag 粒度。
- 为 `Multi` 保存可验证的季度分段。
- 增加季度级续播快照及惰性迁移。
- 同季度换源使用绑定和分段定位正确剧集。

### 阶段三：共用详情页整合

- 详情页按季度汇总所有兼容线路。
- 季度切换同步剧集、线路和续播状态。
- 提供待匹配线路入口和明确的整部节目历史删除操作。

三个阶段共同构成目标方案；分阶段用于控制回归范围，不表示只完成第一阶段即可关闭问题。

## 可观测性

为季度解析和换源记录结构化诊断信息，至少包含：

- TMDB 节目身份。
- 来源绑定键的不可敏感标识。
- 解析出的 `SeasonScope`。
- 使用的证据类型和置信级别。
- 被拒绝的跨季换源原因。
- 绑定失效或降级为 `Unknown` 的原因。

日志不得包含完整播放地址、鉴权参数或 Cookie。

## 测试与验收

### 单元测试

- 中文 `第二季`、`第2季`，英文 `Season 2`、`S02` 能在规则支持范围内识别。
- 明确季度的来源标题应用 TMDB 元数据后不丢失季度信息。
- 同一 TMDB ID 的第一季和第三季投影为两条历史。
- 同一季度的不同来源投影为一条历史。
- 未知季度的不同来源不会因为 TMDB ID 相同而合并。
- `Known(0)` 与 `Unknown` 不混淆。
- 第一季第 5 集和第二季第 5 集分别保存、分别恢复。
- 自动换源只接受同季度或包含该季度的 `Multi` 线路。
- 删除第一季不会删除第二季和第三季进度。

### 集成场景

使用以下场景贯穿解析、详情、播放、历史和删除：

1. 来源 A 为第一季和第二季合集，且能精确切片。
2. 来源 B 为明确第三季。
3. 两者映射到同一 TMDB 电视剧。
4. 详情页只出现一次节目，但能选择第一、二、三季。
5. 第一、二季可选择 A，第三季只能选择 B。
6. 分别播放第一季第 5 集、第二季第 5 集和第三季第 2 集后，三季进度互不覆盖。
7. 历史页显示三条季度记录；删除第二季后，第一季和第三季仍可续播。

### 回归验收

- 电影历史聚合行为不变。
- 单季度电视剧的正常 TMDB 标题和续播行为不退化。
- TMDB 不可用时仍能按原来源播放和记录历史。
- 旧历史不会在升级后被批量误删或错误归到第一季。

## 实施前工作区清理与基线检查

每次开始实施前执行以下流程：

1. 使用 `git status --short --untracked-files=all` 记录基线。
2. 只删除工作区内已确认由工具生成、未跟踪且无复用价值的临时目录，例如重新生成的 `graphify-out`。
3. 对 `build`、Gradle 缓存、依赖目录优先在检索命令中排除，不因“减少检索范围”直接批量删除。
4. 不删除、不覆盖任何已跟踪或用户正在修改的文件。
5. 重新检查与本设计重叠的未提交改动，并在其基础上实施。
6. 检索范围优先限定到 `app/src/main`、`app/src/test` 和相关 `docs`，避免扫描产物目录。

撰写本规格时，工作区已经存在与本问题重叠的未提交代码和测试改动。后续实施必须保留并复核这些改动，不能通过重置工作区获得“干净”基线。

## 备选方案与取舍

### 仅修改历史分组键

优点是改动小，能快速阻止部分展示合并。缺点是合集源仍只有一份进度，自动换源和删除仍可能跨季，因此只能作为第一阶段，不能作为最终设计。

### 每季度完全独立详情页

隔离最彻底，实现思路直接，但同一作品会重复展示元数据，来源线路难以汇总，季度间导航割裂，不符合共用详情页目标。

### 只保留节目级详情和节目级历史

界面最简单，但季度进度天然互相覆盖，无法解决本问题，否决。

### 对所有来源强制猜测季度

表面上能减少 UNKNOWN 记录，但错误续播和错误删除的代价高于重复记录，否决。季度不明时保持隔离是明确的安全边界。

## 完成标准

当以下条件全部满足时，本问题才算完成：

- 标题归一化不再抹掉明确季度。
- 历史、进度、自动换源和删除都使用一致的季度身份。
- 合集线路能按可靠分段服务多个季度。
