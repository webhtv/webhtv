# SEARCH-EMPTY-SOURCE-HIDE 搜索空站源隐藏

## Recovery anchor

- 目标：搜索结果左列不再显示没有任何可见结果的站源；有结果的站源仍保持原有顺序。
- 验收：0% 不限、1%-99% 过滤和 100% 精确三种状态下，无可见结果站源都隐藏；电视端与手机端一致；现有排序、过滤和恢复行为不回退。
- 当前状态：已实施；`SearchSourceVisibilityTest` 在电视端与手机端均为 4/4 通过。
- 下一步：执行任务守卫收尾，提交并创建恢复标签。

## 需求判断

用户反馈“相似度 0% 时，没有搜索结果的站源出现在左列，建议隐藏”是合理的。这里的 `0%` 不是相似度得分为 0，而是当前产品语义中的“不限相似度”。在 0% 状态下，某站源没有可见结果即代表站源没有返回原始结果；继续保留空站源行会增加遥控器和移动端浏览成本。

现有实现里，`1%-100%` 已经会隐藏没有可见匹配的站源，只有 `0% + 固定站源顺序` 保留了空行。该例外源自旧设计：固定顺序允许配置站源暂时为空。但固定顺序真正需要保证的是“可见站源之间的相对顺序”，不是“必须为无结果站源保留占位”。因此应移除该例外。

## 行为设计

统一可见性规则为：

```text
站源至少有一条当前可见结果时显示；否则隐藏。
```

不同相似度状态的含义：

- `0% / 不限`：可见结果等于原始结果；无原始结果的站源隐藏。
- `1%-99%`：可见结果等于通过相似度阈值的结果；无匹配结果的站源隐藏。
- `100% / 精确`：可见结果等于归一化精确匹配结果；无精确匹配的站源隐藏。

站源后续返回第一条可见结果时，仍按当前站源配置顺序插入展示。因此固定顺序模式保留可见站源之间的原顺序，但不保留无结果空行。

## 实施方案

1. 将 `SearchSourceVisibility.shouldShow` 简化为只接收 `hasVisibleResults`。
2. 电视端 `CollectActivity` 和手机端 `CollectFragment` 删除不再需要的 `fixedOrder` 局部变量，并改用新签名。
3. 更新 `SearchSourceVisibilityTest`，删除“0% 固定顺序保留空站源”的旧预期，补充统一隐藏行为。

不改搜索请求、相似度算法、站源健康统计、分页状态和“全部”聚合逻辑。

## 风险与回滚

主要风险是电视端动态插入站源时焦点变化。现有 `1%-100%` 模式已经使用同样的动态显示路径，并通过 `siteKey` 恢复选择；本改动不引入新的排序或焦点恢复机制。

回滚方式：还原本任务的单一提交即可恢复“0% 固定顺序保留空站源”的旧行为。
