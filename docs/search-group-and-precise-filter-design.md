# 搜索分组与相似度过滤设计

> 状态：✅ 已实施并完成双端构建/测试验证
> 日期：2026-07-22（2026-07-27 更新）
> 范围：手机版 `mobile` 与电视版 `leanback` 的影视搜索入口和搜索结果页
> 实施结果：TV 分组入口已改为确认键可见菜单；双端已接入结果分组筛选与 0～100 相似度标题过滤

## 1. 背景与现状判断

### 1.1 当前搜索链路

```text
手机版 SearchActivity / SearchFragment
电视版 SearchActivity
        │
        ├─ 选择搜索范围：全部 / 当前站 / 指定分组
        ▼
手机版 CollectFragment
电视版 CollectActivity
        │
        ▼
SiteViewModel.searchContent(List<Site>, keyword, quick=false)
        │
        ▼
SearchTask -> SiteApi.searchContent()
        │
        ├─ 多站并发结果：getSearch()，按站点逐批返回
        └─ 单站翻页结果：getResult()
```

搜索结果页左侧/顶部的 `Collect` 列表表示“全部 + 各站点”，右侧为当前选中范围内的 `Vod` 列表。

### 1.2 手机版已有能力

手机版当前已经具备两类分组能力：

1. **搜索前限定范围**：`SearchFragment` 的范围菜单支持“全部、当前站、指定分组”，并将 `siteKey/group` 传给 `CollectFragment`，从请求源头减少参与搜索的站点。
2. **搜索后分组筛选**：全局搜索进入 `CollectFragment` 后，可通过 `action_group` 在已返回结果中切换站点分组，不重新发起网络搜索。

`CollectFragment` 使用 `mAllCollectItems` 保存未分组过滤的站点结果，然后通过 `mFilterGroup` 派生当前展示列表。这部分是电视版结果页最适合参考的实现。

### 1.3 电视版实际现状

当前代码不是完全没有分组能力，而是存在两个问题：

1. `SearchActivity` 已经支持分组搜索范围，但入口隐藏在 `searchScope` 的**长按**操作中；普通确认键只在“全部/当前站”之间切换。对遥控器用户来说几乎不可发现，因此产品体验上等同于“没有分组搜索”。
2. `CollectActivity` 只支持搜索前传入的 `group`，没有手机版结果页已有的“搜索后按站点分组即时筛选”。

因此本设计把“电视版分组搜索”拆成两个补齐项：

- 搜索页：让分组范围选择可见、可发现。
- 结果页：增加无需重搜的分组二次筛选。

## 2. 目标

1. 电视版使用遥控器确认键即可选择“全部、当前站、指定分组”，不依赖长按隐藏手势。
2. 电视版全局搜索结果页具备与手机版一致的站点分组二次筛选。
3. 手机版和电视版搜索结果页都提供 0～100 相似度滑杆：0 为不限，100 为归一化标题精确匹配。
4. 分组过滤与相似度阈值可以同时生效，并按 AND 关系组合。
5. 所有原始搜索结果必须保留在内存中，相似度调回 0 后立即恢复，不重新请求网络。
6. 不改变搜索接口、不影响站点健康统计、不引入第三方相似度依赖。

## 3. 非目标

本期不处理以下内容：

- 不做语义别名匹配，例如“哈利波特”和“Harry Potter”。
- 不做拼音、谐音、AI 标题理解。
- 不使用演员、导演、简介、类型或备注参与相似度匹配，只匹配 `Vod.getName()`。
- 不对搜索结果去重。
- 不改变站点原始结果排序，也不按相似度重新排序。
- 不提供多套匹配算法或按站点独立阈值；双端统一使用 0～100 相似度。
- 不把过滤下沉到爬虫、`SiteApi` 或服务端。

## 4. 核心设计原则

### 4.1 原始数据与展示数据分离

相似度过滤是可逆的界面过滤，不能直接删除 `Result.getList()` 或 `Collect.getList()` 中的原始数据。

每个结果页维护两层状态：

```text
原始层 Raw
  各站点已经返回的全部 Vod
  各站点翻页页码
  站点原始顺序

展示层 Projection
  站点分组过滤
  AND 相似度标题过滤
  -> 全部聚合项
  -> 可见站点项
  -> 当前右侧结果
```

所有网络结果先写入原始层，再根据当前过滤状态生成或增量更新展示层。切换过滤只重新投影，不重新搜索。

### 4.2 相似度过滤放在结果聚合层

相似度过滤应在 `CollectFragment/CollectActivity` 接收到结果后执行，而不是放在 `SearchTask`、`SiteApi` 或 `SiteViewModel` 中，原因如下：

- 用户可以随时把相似度调回 0 并恢复已经加载的数据。
- `SiteHealthStore.recordSearch()` 继续记录站点真实返回数量，不会因为本地相关性规则而错误降低站点健康度。
- 搜索进度仍以完成站点数计算，与过滤结果多少无关。
- 单站翻页和多站并发结果可以使用同一过滤逻辑。

### 4.3 过滤不改变排序

达到当前相似度阈值的条目保持站点返回顺序；“全部”聚合保持当前站点顺序：

- 动态模式：按站点响应顺序。
- 固定模式：按配置站点顺序。

## 5. 电视版分组搜索设计

### 5.1 搜索页范围选择

#### 当前问题

`searchScope` 单击仅切换“全部/当前站”，长按才显示完整分组菜单，缺乏可发现性；当前弹窗宽度固定为 `136dp`，长分组名还可能截断。

#### 调整方案

- `searchScope` 的普通确认键直接打开完整范围菜单。
- 菜单选项顺序：
  1. 全部
  2. 当前站
  3. 配置中解析出的所有站点分组
- 长按可以保留为打开同一菜单的兼容入口，但不再承载独占功能。
- 按钮文本始终显示当前范围：`全部 / 当前站 / 分组名`。
- 建议增加下拉箭头或选中态，明确它是可展开选择器。
- 弹窗宽度根据最长文本动态计算；高度最多显示 8 项，超过后滚动。
- 弹窗打开后默认聚焦当前选中项。
- “当前站”不可搜索时沿用现有提示，并保持原选择不变。

#### 请求行为

- 选择“全部”：`siteKey=""`、`group=""`。
- 选择“当前站”：传当前 `siteKey`、`group=""`。
- 选择分组：`siteKey=""`、传对应 `group`。

这部分是搜索前限定范围，会真实减少 `mSites` 和并发请求数量。

### 5.2 电视版结果页分组二次筛选

在 `activity_collect.xml` 顶部操作区增加可聚焦的分组按钮，位置建议为：

```text
搜索结果标题                    [分组：全部] [相似 30%] [布局]
```

行为：

- 仅当本次是全局搜索，且存在至少一个分组时显示。
- 当前站搜索或搜索前已经限定分组时隐藏，避免产生含义冲突。
- 确认键打开“全部 + 分组列表”。
- 切换分组只过滤已经加载的站点和结果，不发起新请求。
- 后续异步返回的站点结果仍写入原始层；只有属于当前分组的结果进入展示层。
- 当前选中站点在新分组中仍存在时保留选择，否则回退到“全部”。
- 切换后右侧结果滚动到顶部。

电视端实现可参考手机版 `CollectFragment` 的 `mAllCollectItems`、`mFilterGroup`、`getFilteredCollectItems()` 流程，但不能继续把 Adapter 数据当作唯一真源。

## 6. 双端相似度搜索过滤设计

### 6.1 交互形态

相似度过滤采用结果页 0～100 滑杆，并记住用户上次选择：

- 手机版：`menu_collect.xml` 的 `action_similarity` 显示当前值，点击后打开 `SliderNumberDialog`。
- 电视版：顶部可聚焦的 `similarityFilter` 按钮显示当前值，点击后打开同样的滑杆。
- 状态通过 `Setting.getSearchSimilarity()` / `Setting.putSearchSimilarity(int)` 保存并限制在 0～100；首次默认值为 30。
- `0` 表示不限，原始结果全部进入展示投影。
- `1～99` 表示按当前阈值保留标题，并动态隐藏没有任何匹配结果的站点线路。
- `100` 表示归一化标题精确匹配；标题包含和编辑距离结果不会达到 100。
- 调整数值后立即对已加载结果重新投影，不重新请求；调回 0 时立即恢复原始结果。
- 无匹配结果时显示可操作空状态，提示用户降低相似度查看更多。

按钮标题统一按端点显示为“不限 / 相似 xx% / 精确”，避免把 100% 描述成普通模糊相似度。

### 6.2 匹配字段

第一版只使用：

```java
Vod.getName()
```

不使用 `typeName`、`remarks`、`actor`、`director`、`content`，否则“标题不相关、详情文本碰巧包含关键词”的结果会重新进入列表，失去标题相似度过滤意义。

### 6.3 文本归一化

新增共享纯逻辑类，建议：

```text
app/src/main/java/com/fongmi/android/tv/utils/SearchResultFilter.java
```

归一化步骤：

1. 空值转空字符串。
2. `Trans.t2s()` 将繁体转为简体，与现有搜索任务保持一致。
3. Unicode NFKC 归一化，统一全角/半角字符。
4. 使用 `Locale.ROOT` 转小写。
5. 将明确的季/部表达标准化为数字，例如：
   - `第二季`、`第2季`、`Season 2`、`S02` -> `2`
   - 只处理带“季/部/Season/S”语义的数字，不删除普通片名数字。
6. 标点和空白统一处理：
   - 保留一份 token 文本，供短英文词整词判断。
   - 生成一份仅含 Unicode 字母和数字的 compact 文本，供精确、包含和编辑距离比较。
7. 不删除普通年份或片名尾部数字，避免把《无间道2》和《无间道3》视为同一标题。

不直接复用 `MediaTitleParser.cleanTitle()`：该类为了 TMDB/弹幕检索会主动移除年份、季号和部分尾部数字，适合生成搜索候选词，但对“相似度结果过滤”过于激进，容易合并不同续集。

### 6.4 评分与阈值判定

每个标题先计算 `0～100` 的整数分数，再用 `score >= similarityPercent` 决定是否展示：

#### A. 完全匹配

```text
normalizedTitle == normalizedKeyword -> 100
```

这是唯一能得到 100 的路径，因此滑杆设为 100 时就是归一化标题精确匹配。

#### B. 标题包含搜索词

```text
score = round(keywordLength * 100 / titleLength)
score = min(score, 99)
```

限制：

- 关键词 compact 长度至少为 2；一字关键词不会通过包含规则扩大召回。
- 中文或长度至少 3 的英文/数字关键词使用 compact 包含。
- `IT`、`UP`、`US` 等两个字符的英文标题使用 token 整词匹配，避免 `IT` 误命中 `Little Women`。
- 包含位置不能切断同一数字 token，例如 `2` 不应命中 `20`。
- 不采用“搜索词包含结果标题”的反向包含，避免更具体的续集、年份或版本错误保留基础标题。

#### C. 编辑距离相似度

仅在未命中 A/B 时执行 Levenshtein 编辑距离：

```text
score = round((1 - editDistance(title, keyword) / maxLength) * 100)
```

保护条件：

- 两侧最大长度必须至少为 4。
- 长度差不得超过 `max(2, floor(maxLength * 0.2))`。
- 搜索词包含数字时，候选标题提取出的数字序列必须完全一致。

这些保护可避免 `无间道2` 误命中 `无间道3`、`三体2023` 误命中 `三体2024`。最终是否保留不再使用语言相关的固定阈值，而是统一由用户当前选择的 0～100 阈值决定。

### 6.5 示例

| 搜索词 | 结果标题 | 阈值 | 结论 | 原因 |
|---|---|---:|---:|---|
| `庆余年` | `庆余年2` | 75 | 保留 | 包含覆盖率为 75 |
| `庆余年` | `庆余年2` | 76 | 过滤 | 未达到当前阈值 |
| `庆余年2` | `庆余年 第二季` | 100 | 保留 | 季号标准化后完全匹配 |
| `流浪地球2` | `流浪地求2` | 80 | 保留 | 编辑距离得分为 80，数字一致 |
| `流浪地球2` | `流浪地求2` | 81 | 过滤 | 未达到当前阈值 |
| `长相思` | `长相守` | 80 | 过滤 | 最大长度小于 4，不执行编辑距离 |
| `无间道2` | `无间道3` | 80 | 过滤 | 数字序列冲突 |
| `IT` | `IT Chapter Two` | 15 | 保留 | 短英文整词匹配且覆盖率达到阈值 |
| `IT` | `Little Women` | 15 | 过滤 | 不是整词匹配 |
| `囧` | `囧` | 100 | 保留 | 一字标题归一化后完全匹配 |
| `囧` | `泰囧` | 30 | 过滤 | 一字关键词不参与包含匹配 |

### 6.6 结果投影规则

最终展示条件：

```text
siteMatchesSelectedGroup
AND
(similarityPercent == 0 OR SearchResultFilter.matches(keyword, vod.name, similarityPercent))
```

“全部”项必须由过滤后的各站点列表重新聚合，不能继续引用原始总列表。

#### 固定站点顺序模式

- 相似度为 0 时保持固定顺序语义，配置中的站点行可以暂时为空。
- 相似度为 1～100 时改为动态展示：当前没有任何匹配结果的站点立即隐藏，不等待初始搜索或分页结束。
- 搜索或进行中的分页回调一旦产生首条匹配结果，该站点按配置顺序重新出现。

#### 动态站点顺序模式

- 相似度为 0 时，只有至少一条原始结果的站点进入站点列表。
- 相似度为 1～100 时，只有至少一条当前阈值匹配结果的站点进入站点列表。
- 调整相似度后从原始层重新投影：不匹配的线路立即隐藏，重新达到阈值的线路无需重新搜索即可恢复。

“全部”始终保留。筛选标题按端点显示为“不限 / 相似 xx% / 精确”，避免把 100% 继续描述成普通相似度。

## 7. 异步、翻页与状态一致性

### 7.1 多站并发结果

每个 `getSearch()` 回调按以下顺序处理：

1. 将完整 `Result.getList()` 写入对应站点的原始列表。
2. 根据当前分组判断站点是否可见。
3. 根据当前相似度阈值过滤本批条目。
4. 增量更新当前展示，或在过滤状态刚变化时执行完整投影。
5. 搜索进度无论本批是否有可见条目都正常递增。

### 7.2 单站翻页

翻页结果必须先追加到原始站点列表，再追加当前可见子集：

- 相似度大于 0 时，当前页中未达到阈值的条目只保存在原始层。
- 相似度调回 0 后，所有已加载页中的隐藏条目立即恢复。
- 页码保存到原始站点状态，不能只写到临时展示副本。
- 翻页请求发出时只记录“站点 + 待请求页”，收到该站点的非空结果后才提交页码；空结果、错误结果和错站结果均不推进页码。
- 同一结果页同一时间只允许一个单站翻页请求。切换分组、相似度或选中站点不会清除该请求，也不会发起会取消它的新请求。
- 即使当前分页整批都被相似度过滤隐藏，展示副本已有站点项时也要同步页码；切换站点恢复分页时始终优先读取原始层页码。
- 当前选中站点的某一页有原始数据但整页未达到相似度阈值时，自动继续请求下一页，直到出现可见条目、到达明确总页数或服务端返回空页。
- 每个站点记录已接收页面的稳定条目签名；若未知总页数的站源重复返回相同非空页，则不追加重复数据、不提交页码，并停止该站点继续翻页，避免自动请求循环。
- 若过滤切换使站点项暂时消失，进行中的分页随后产生首批可见结果时，应按原始站点顺序重新创建展示投影，并在“全部”处于激活状态时同步追加右侧列表。

### 7.3 过滤切换时的选中项

- 优先按 `siteKey` 恢复原选中站点，不按旧 position 恢复。
- 原站点被分组隐藏或在动态模式下无可见结果时，回退到“全部”。
- 右侧列表滚动到顶部。
- 电视版如果当前焦点位于即将消失的条目，应把焦点移到“相似度”按钮或首个可见结果，避免焦点丢失。

## 8. 建议代码改动范围

### 8.1 共享代码

```text
app/src/main/java/com/fongmi/android/tv/utils/SearchResultFilter.java
app/src/main/java/com/fongmi/android/tv/utils/SearchSourceVisibility.java
app/src/main/java/com/fongmi/android/tv/setting/Setting.java
app/src/main/res/values/strings.xml
app/src/main/res/values-zh-rCN/strings.xml
```

`SearchResultFilter` 保持纯函数、无 Android View 依赖，便于 JVM 单元测试。

### 8.2 手机版

```text
app/src/mobile/java/com/fongmi/android/tv/ui/fragment/CollectFragment.java
app/src/mobile/res/menu/menu_collect.xml
app/src/mobile/res/layout/fragment_collect.xml（空状态，如采用）
```

重点：

- `mAllCollectItems` 是包含完整结果、站点顺序和分页页码的唯一原始层，Adapter 中的 `Collect` 仅是展示副本。
- 使用按 `siteKey` 保存的 `mVisibleItems` 缓存当前相似度下的可见条目；多站回调和分页回调只过滤本批新增结果并追加缓存，避免每次结果到达都重新处理全部历史标题。
- 仅在相似度值变化时通过 `rebuildVisibleItems()` 全量重建缓存；分组切换只重新聚合已有缓存，不重复执行繁简转换、正则和编辑距离。
- `getFilteredCollectItems()` 从可见缓存复制列表并生成 Adapter 投影，分页和选中恢复始终按 `siteKey` 回到原始对象读取状态。

```text
app/src/leanback/java/com/fongmi/android/tv/ui/activity/SearchActivity.java
```

## 11. 风险与控制

### 11.1 误过滤有效结果

风险：别名、译名、缩写或短标题无法通过字面规则。

控制：

- 首次默认 30%，用户可随时调到 0 立即恢复全部结果。
- 100 仅允许归一化标题完全相等，包含与模糊匹配最高只能得到 99。
- 不把过滤结果写回缓存或数据库。
- 不影响原始网络数据和站点健康评分。

### 11.2 原始列表和展示列表混用

风险：调整相似度后数据丢失、翻页追加到临时副本、调回 0 无法恢复。

控制：

- 原始层是唯一真源。
- Adapter 只保存展示投影。
- 所有网络回调先写原始层。
- 使用 `siteKey` 定位原始站点，不依赖当前 Adapter position。
- TV 延迟切换与延迟刷新均保存 `siteKey`，执行时重新解析当前 Adapter position，避免动态插入线路后错刷或丢失选中结果。

### 11.3 电视版焦点回归

风险：顶部新增按钮、弹窗和动态隐藏站点可能导致焦点丢失或方向键死区。

控制：

- 明确顶部按钮顺序和 `nextFocus*`。
- 弹窗打开后聚焦当前项。
- 过滤后校验焦点 View 是否仍 attached/visible。
- 在电视真机或模拟器覆盖横向、纵向结果布局。

### 11.4 过滤性能

标题通常较短，Levenshtein 仅在精确和包含都失败后执行；对几百到一两千条结果成本可控。实现时应复用一次归一化后的 keyword，避免每个条目重复处理搜索词。当前实现通过可见结果缓存避免每批回调全量重算；若真机测量仍出现明显卡顿再进一步优化。

## 12. 实施顺序

1. 新增 `SearchResultFilter` 与单元测试，固定匹配规则。
2. 重整手机版结果页的原始层/展示层边界，并接入相似度滑杆。
3. 参照手机版给电视版结果页增加原始结果容器和分组过滤。
4. 给电视版接入相似度过滤，保留现有懒加载和滚动优化。
5. 将电视版搜索页范围按钮改为单击完整菜单。
6. 补齐双端空状态、字符串、无障碍描述和 TV 焦点规则。
7. 运行双 flavor 单测、构建和手工验证矩阵。

## 13. 验收标准

- TV 搜索页不使用长按也能选择任意站点分组。
- TV 全局搜索结果页可以在“全部/分组”之间切换，且不重新发起搜索。
- 手机版原有分组过滤行为不回归。
- 双端都能在 0～100 调整相似度，并在调回 0 后恢复全部已加载结果。
- 相似度过滤至少正确处理完全匹配、标题包含覆盖率、季号等价、编辑距离和数字冲突。
- 分组与相似度同时生效时结果正确，后续异步结果和翻页结果遵循当前阈值。
- 过滤不改变站点请求数量、搜索进度和站点健康统计。
- TV 遥控器焦点无丢失、无不可达控件、无方向键死区。
- 双端单元测试和 Debug 构建通过。

## 14. 建议结论

建议采用“**搜索前范围限制 + 搜索后可逆过滤**”的双层方案：

- 搜索前分组用于减少请求，解决效率问题。
- 搜索后分组用于快速查看已返回数据，解决浏览问题。
- 相似度过滤作为可持久记忆的 0～100 结果页滑杆，使用“完全匹配 -> 标题包含覆盖率 -> 编辑距离”的评分规则。
- 原始结果始终保留，所有过滤都只作用于展示投影。

该方案复用手机版已有分组思路，同时补齐电视端的可发现性、结果页一致性和可逆相似度过滤，风险主要集中在结果状态分层与 TV 焦点，均可通过上述数据边界和测试矩阵控制。
