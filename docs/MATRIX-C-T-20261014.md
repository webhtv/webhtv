### 1.1 应用密度是 2.0，不是系统配置里的 3.0

这一点**必须先确定**，否则所有 dp↔px 换算都会错。用布局里已知 dp 的控件反推（`uiautomator` 实测像素）：

| 控件 | 布局声明 | 实测 | 推出密度 |
|---|---|---|---|
| `activity_home.xml` 的 `logo` | 48dp × 48dp | 96 × 96 px | **2.0** |
| `activity_home.xml` 的 `toolbar` 高 | 24dp(padTop) + 48dp(logo) + 8dp(padBottom) = 80dp | 160 px | **2.0** |
| `toolbar` 的 `paddingStart` | 24dp | 内容起点 x = 48 px | **2.0** |

三处独立吻合，且 `ResUtil.dp2px(16)` 在设备上产生 32px（= 16dp × 2），与之一致。
**结论：应用 Resources 运行在 density 2.0（320dpi），而系统 `Configuration` 报 480dpi。**
这是本仓库既有行为（`App.getResources()` 会 `updateConfiguration`，见 `App.java:213-226`），
非本次改动引入；对验收的影响是**换算必须用 2.0**。

## 3. 原缺陷记录：TV 横向间距 20dp 未达成

### 3.1 标准与 token

设计文档 line 610–612、705、1173 三处都要求 **TV 横向列表项间距 20dp**。设计系统为此定义了 token：

```
app/src/main/res/values/webhtv_dimens.xml:11
    <dimen name="webhtv_size_tv_card_gap">20dp</dimen>
```

### 3.2 该 token 从未被引用

```
grep -r webhtv_size_tv_card_gap app/src   →  1 处命中，就是它自己的声明
```

**只声明、没接线。** 与此前审计发现的 `webhtvColorScrim` / `webhtvColorOverlayDark` /
`webhtvColorOverlayLight`「只声明、从未赋值」属同一类缺陷。

### 3.3 实际间距是各调用点硬编码的 8/10/12/16dp

| 位置 | 值 |
|---|---|
| `HomeActivity.java:517/518/519` | `new CustomRowPresenter(16)`（VodPresenter / FuncPresenter / HistoryPresenter 三行） |
| `TypeFragment.java:159` / `:160` | `CustomRowPresenter(16)` / `CustomRowPresenter(8)` |
| `CollectFragment.java:82` | `CustomRowPresenter(16)` |
| `adapter_episode_card.xml` | `android:layout_marginEnd="12dp"` |
| `HomeActivity.java:522`、`VodActivity.java:156` | `setHorizontalSpacing(ResUtil.dp2px(16))` |
| `VideoActivity.java:1737-1799`、`:3831`、`:3908` | 8dp / 12dp |

`CustomRowPresenter.java:70` 是 TV 行间距的唯一落点：
`grid.setHorizontalSpacing(ResUtil.dp2px(spacing))`，`spacing` 由各调用点传入。
**没有任何调用点传 20dp，也没有任何调用点读该 token。**
反查确认：leanback 里 `20dp` 出现 40 处，**全部**是 padding / margin / 图标尺寸 / 圆角。

### 3.4 设备实测（修复前）

`uiautomator dump` 得到「更新推荐」行卡片精确 bounds（1920×1080 px）：

```
x = 48, 419, 790, 1161, 1532   每张宽 339
相邻间距 = 32 px = 16 dp（按 §1.1 的 density 2.0）
```

即渲染结果与 `CustomRowPresenter(16)` **完全一致**——代码没错，只是**值是 16dp 而非标准要求的 20dp**。

### 3.5 承载该标准的测试名不符实

```
app/src/test/java/com/fongmi/android/tv/ui/style/UiLayoutSourceTest.java:33-39
    public void tvCardsUseTheSharedCardGapTokenAndRoundedFamily() throws Exception {
        String card = Files.readString(Path.of("src/leanback/res/layout/adapter_episode_card.xml"), …);
        assertTrue("TV episode cards must keep the shared rounded family",
                card.contains("app:cardCornerRadius=\"@dimen/webhtv_card_radius_default\""));
        assertFalse("TV episode card colours must be token-only", card.matches("(?s).*#[0-9A-Fa-f]{6,8}.*"));
    }
```

方法名含 `GapToken`，但函数体**没有断言任何间距值**。因此设计文档两处描述不成立：

- §19.3（line 1435）：「卡片比例、**TV 20dp**、安全区、焦点/状态、无未豁免固定色」；
- §21（line 1180）：「列表/卡片几何测试（新增 `UiLayoutSourceTest`）断言比例、**20dp TV 间距**、2:3/16:9」。

### 3.6 首页卡片没有声明比例

`adapter_vod.xml`（leanback 首页「最近观看 / 更新推荐」卡片）根节点是 `wrap_content × wrap_content`，
图片只声明 `android:layout_height="80dp"`，**没有声明任何比例**。设备实测卡片 339×547，
其中 `ImageView` 339×452 → **3:4**，既不是 2:3 也不是 16:9。

## 6. 局限与遗留

1. **密度前提**：本行全部 dp↔px 换算基于 §1.1 实测的应用密度 2.0。系统 `Configuration` 报 480dpi，
   两者不一致是既有行为；若在别的设备上密度不同，像素值会变，但 dp 结论不变。
2. **遗留（未修）**：`adapter_vod.xml` 未声明卡片比例，实测 3:4（§3.6）。
   修它需要先决定首页卡片该用 2:3 还是按内容类型区分，属设计决策，未纳入本次最小范围。
3. **遗留（未修）**：`VodActivity`、`VideoActivity`、各 Dialog 的横向间距仍是 8/12/16dp。
   若要让"TV 横向间距 20dp"在**全 TV 范围**成立，需要另一批独立改动 + 独立验证。
4. 设计文档 §19.3 / §21 对 `UiLayoutSourceTest` 的描述仍有未兑现部分（**安全区**、**焦点/状态**两项
   仍未被该测试断言）；本次只补齐了「TV 20dp」这一项。
5. 设备是 1920×1080 / density 2.0（= 960×540dp，恰好等于设计文档的 TV 基准），
   但它是模拟器，观感不能完全外推到真机。
6. 本行未做 D-pad 全量可达性遍历。
