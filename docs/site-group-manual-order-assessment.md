# 站点分组标签手动排序需求评估

- 评估日期：2026-08-09
- 反馈位置：移动端站点选择弹窗中，搜索框下方的分组标签行（截图中的“注入 / 首页 / 直播 / 影视 / 4K”）
- 评估结论：**建议接受，按移动端中优先级（P2）的小型体验优化排期**

## 1. 结论摘要

这个需求有明确用户价值，而且与现有“站点条目长按拖动排序”的交互心智一致，技术上可行，风险可控。

建议将需求收口为：

> 用户可在站点选择弹窗中长按某个分组标签并左右拖动，仅调整分组标签的展示顺序；排序按当前点播配置独立保存，重新打开弹窗后仍然生效。

推荐先做 **移动端 MVP**：

1. 长按标签进入拖动，左右移动完成排序；
2. 排序结果按当前 VOD 配置保存；
3. 未排序用户保持现有默认顺序；
4. 新产生的分组自动追加在已有自定义顺序之后；
5. 分组改名视为“旧分组消失、新分组出现”；
6. 只改变标签顺序，不改变站点顺序、分组规则或站点归属。

预估：

| 范围 | 预估工作量 | 风险 |
|---|---:|---|
| 仅截图中的移动端分组标签排序 | 1～1.5 人日 | 中低 |
| 同时统一移动端搜索范围、聚合页等分组展示顺序 | 1.5～2 人日 | 中低 |
| 再补电视端遥控器排序能力 | 额外 1～1.5 人日 | 中 |

估算包含实现、单元测试、编译验证和真机交互回归，置信区间约 ±30%。

## 2. 用户需求解读

截图里 `4K` 位于标签行末尾。分组较多时，用户每次打开站点弹窗都可能需要横向滑动，才能进入高频分组。用户希望把常用分组提前，本质上是一个“高频入口个性化”需求。

该需求不是修改分组内容，而是修改分组的 **显示优先级**。建议明确排除以下容易混淆的能力：

- 不在这里创建、删除或重命名分组；
- 不修改站点属于哪个分组；
- 不联动调整站点条目的顺序；
- MVP 不做账号同步、云端同步或跨设备同步；
- MVP 不承诺移动端与电视端共享排序结果。

## 3. 当前实现分析

### 3.1 当前分组顺序不是用户可控顺序

移动端弹窗在以下位置生成分组：

- `app/src/mobile/java/com/fongmi/android/tv/ui/dialog/SiteDialog.java:170`
- `app/src/main/java/com/fongmi/android/tv/bean/Site.java:335`

`Site.getGroups(List<Site>)` 使用 `LinkedHashSet` 收集分组，因此当前顺序实际是：

1. 按配置中的站点原始顺序遍历；
2. 取每个站点名称中由分组规则提取出的标签；
3. 某个分组第一次出现的位置，决定它在标签行中的位置。

所以当前排序既不是字母顺序，也不是使用频率顺序，而是受站点配置顺序、站点别名和分组规则共同影响。对用户而言，这个顺序容易显得随机。

### 3.2 分组标签是动态 View，不具备现成拖动能力

当前布局：

- `app/src/mobile/res/layout/dialog_site.xml:67`
- `app/src/mobile/res/layout/dialog_site.xml:77`

采用 `HorizontalScrollView + LinearLayoutCompat`。`SiteDialog` 运行时逐个创建 `MaterialButton` 并加入 `groupList`。

这意味着不能直接复用 Android 的 `ItemTouchHelper`；它只对 `RecyclerView` 提供成熟的拖动排序支持。若在现有 `HorizontalScrollView` 上手写触摸坐标、交换位置和边缘自动滚动，代码量看似少，但手势冲突和机型兼容风险更高，不建议采用。

### 3.3 项目已有“站点条目手动排序”先例

站点列表已经支持长按条目拖动：

- `app/src/mobile/java/com/fongmi/android/tv/ui/dialog/SiteDialog.java:100`
- `app/src/mobile/java/com/fongmi/android/tv/ui/adapter/SiteAdapter.java:125`
- `app/src/main/java/com/fongmi/android/tv/setting/SiteOrderStore.java:17`

现有链路是：

1. 长按站点条目；
2. `ItemTouchHelper` 开始拖动；
3. `SiteAdapter.drag()` 调整列表；
4. `SiteOrderStore` 按当前 `VodConfig.getCid()` 保存站点 key 顺序。

该能力在 2026-07-01 的提交 `4aef43731a` 中引入，共涉及 3 个文件、118 行新增代码。分组排序可以沿用同一交互模型和持久化思路，因此可行性较高。

### 3.4 分组还出现在其他界面

除截图中的站点弹窗外，`Site.getGroups(...)` 还用于：

- 移动端搜索范围菜单：`app/src/mobile/java/com/fongmi/android/tv/ui/fragment/SearchFragment.java:326`
- 移动端聚合结果：`app/src/mobile/java/com/fongmi/android/tv/ui/fragment/CollectFragment.java:251`
- 电视端站点弹窗、搜索范围菜单和聚合结果界面

如果仅在站点弹窗应用自定义顺序，移动端不同入口可能出现顺序不一致。建议排序入口先放在截图中的弹窗，但移动端其他用户可见分组列表也读取同一排序结果。

## 4. 方案比较

| 方案 | 描述 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 标签行直接长按左右拖动 | 将标签行改为横向 `RecyclerView`，用 `ItemTouchHelper` 排序 | 最直接；符合用户预期；与站点列表手势一致；不增加弹窗层级 | 需要改造当前标签容器；需处理横滑与长按拖动边界 | **推荐用于移动端 MVP** |
| B. 新增“分组排序”管理弹窗 | 点击排序按钮后，在独立纵向列表中拖动或点上下按钮 | 可增加恢复默认；无障碍和电视遥控器操作更完整 | 新增按钮、弹窗、布局和状态回调，明显扩大“小建议”的实现范围 | 适合作为电视端或增强版 |
| C. 根据站点条目顺序推导分组顺序 | 让分组顺序跟随站点手动排序 | 改动较小 | 一个站点可命中多个分组；分组顺序被站点排序隐式改变，用户难以理解；无法独立控制 | **不建议** |
| D. 保留 `HorizontalScrollView`，手写拖动 | 直接监听触摸和拖放事件 | 表面上少一个 Adapter | 横向滚动、长按、边缘自动滚动、拖动阴影和取消事件都需自行处理，回归风险最高 | **不建议** |

## 5. 推荐交互

### 5.1 基本行为

- 单击标签：保持现有行为，筛选对应分组；
- 再次单击已选标签：保持现有行为，取消分组筛选；
- 长按标签：触发轻微震动并进入拖动；
- 左右拖动：标签跟随手指移动，其他标签让位；
- 松手：立即保存新顺序；
- 拖动过程中：保持当前 `selectedGroup` 不变，不重新筛选站点列表；
- 开始拖动时：隐藏软键盘，避免搜索框和拖动同时抢占空间。

### 5.2 排序作用域

建议按当前点播配置独立保存，行为与现有 `SiteOrderStore` 保持一致：

- 配置 A 和配置 B 可以有不同顺序；
- 切换配置后加载各自顺序；
- 删除并重新创建配置时，MVP 可以接受顺序重置；
- 排序保存在本机偏好设置中，不承诺跨设备同步。

### 5.3 动态分组处理

分组来自站点名称和可配置规则，不是稳定数据库实体，因此必须定义兼容策略：

- 新增分组：追加到自定义顺序末尾；
- 删除分组：界面中忽略，保存时可清理陈旧名称；
- 分组改名：按“旧名称删除、新名称新增”处理；
- 重复分组：继续由 `LinkedHashSet` 去重；
- 没有保存过顺序：完全沿用当前默认顺序，保证老用户无行为变化。

## 6. 推荐技术方案

### 6.1 新增独立排序存储

建议新增：

`app/src/main/java/com/fongmi/android/tv/setting/SiteGroupOrderStore.java`

职责保持单一：

- 加载当前配置的分组名称顺序；
- 将保存顺序应用到当前可用分组；
- 保存新的分组顺序；
- 忽略无效、重复和已经不存在的名称；
- 未知的新分组按当前默认顺序追加。

建议使用独立 key，例如：

```text
site_group_order_<cid>
```

不建议为了这一项功能抽象通用的“万能排序框架”；现有站点排序类很小，新增对应的小型 Store 更直观，也更符合当前代码结构。

### 6.2 将移动端标签行改为横向 RecyclerView

建议把移动端 `HorizontalScrollView + LinearLayoutCompat` 改为：

- 横向 `RecyclerView`；
- 一个轻量 `SiteGroupAdapter`；
- `ItemTouchHelper.SimpleCallback(LEFT | RIGHT, 0)`；
- 长按后启动拖动；
- 在拖动结束时统一保存，避免每经过一个位置都写偏好设置。

标签的颜色、描边、选中态和间距继续沿用当前 Material 样式，避免视觉变化。

### 6.3 处理“屏蔽站点”造成的部分分组集合

当前普通模式会排除被屏蔽站点，而“显示屏蔽站点”模式会重新加入它们。因此某些分组可能只在其中一种模式出现。

不能简单用当前屏幕上的标签列表覆盖全部已保存顺序，否则切换屏蔽模式后，暂时不可见分组的位置会丢失。

建议保存时采用“可见子集重排、不可见项保留原相对位置”的合并策略：

1. 先取得包含全部站点时的完整分组集合；
2. 将用户当前拖动的可见分组顺序合并回完整顺序；
3. 未出现在当前视图中的分组保持原相对位置；
4. 再保存完整结果。

这部分是实现中最需要单元测试的边界。

### 6.4 移动端其他分组入口保持一致

推荐让以下界面读取 `SiteGroupOrderStore` 排序结果：

- `SiteDialog`



- `SearchFragment` 的搜索范围菜单
- `CollectFragment` 的分组展示

只有 `SiteDialog` 提供编辑入口，其他界面只读取顺序。这样不会增加额外交互，却可避免同一设备上不同页面顺序不一致。

## 7. 验收标准

1. 没有自定义顺序时，标签顺序与当前版本完全一致；
2. 用户可长按任一分组标签并左右拖动；
3. 拖动完成后，当前选中分组、站点筛选结果和滚动状态不发生异常跳变；
4. 关闭并重新打开站点弹窗，顺序仍然保留；
5. 重启应用后顺序仍然保留；
6. 不同点播配置的分组顺序互不影响；
7. 新分组自动追加，已删除分组不显示，也不会产生空标签；
8. 分组改名后，新名称按新分组处理；
9. 切换“显示/隐藏屏蔽站点”不会破坏暂时不可见分组的顺序；
10. 搜索框有文字、键盘弹出时，长按拖动仍能正常开始；
11. 单列/双列站点布局切换不影响标签排序；
12. 竖屏、横屏以及窄屏设备上可正常横向滚动和拖动；
13. 标签按钮保留可访问描述，至少表达“分组名称”和“长按可排序”；
14. 排序只影响分组标签的显示顺序，不改变站点列表的手动顺序。

## 8. 测试建议

### 8.1 单元测试

为纯排序/合并逻辑覆盖：

- 无保存顺序时保持默认；
- 完整保存顺序正常应用；
- 新分组追加；
- 陈旧分组忽略或清理；
- 重复名称去重；
- 可见子集重排时，不可见分组相对位置保持；
- 配置切换使用不同存储 key。

建议把“排序合并算法”写成无 Android 依赖的 package-private 纯函数，以便普通 JVM 单元测试直接验证。

### 8.2 真机回归

- 普通模式与显示屏蔽站点模式；
- 搜索框空/非空、键盘显示/隐藏；
- 标签数量 2、5、10+；
- 长标签、中文标签、英文/数字标签；
- 竖屏和横屏；
- 拖到首位、末位以及横向可视区域之外；
- 排序后关闭弹窗、切换配置、重启应用。

## 9. 改动范围预估

移动端 MVP 预计涉及 5～7 个文件：

| 文件/区域 | 改动 |
|---|---|
| `SiteGroupOrderStore.java` | 新增分组顺序持久化与合并逻辑 |
| 移动端 `SiteDialog.java` | 接入分组 Adapter、拖动回调和排序保存 |
| 移动端 `dialog_site.xml` | 将分组标签容器改为横向 RecyclerView |
| 分组标签 Adapter 或 item layout | 新增可复用标签渲染与选中态 |
| `SearchFragment.java` | 可选但推荐：读取统一顺序 |
| `CollectFragment.java` | 可选但推荐：读取统一顺序 |
| 单元测试 | 覆盖排序、动态分组和部分集合合并 |

预计新增/修改约 200～350 行代码。性能影响可忽略：分组数量通常很小，排序和合并均可控制在 O(n) 或 O(n log n)。

## 10. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 横向滚动与长按拖动手势冲突 | 中 | 使用横向 RecyclerView + ItemTouchHelper；仅长按后进入拖动；开始时提供震动反馈 |
| 分组名称动态变化导致保存项失效 | 中低 | 以当前有效分组为准，未知项追加，陈旧项忽略/清理 |
| 屏蔽模式只显示部分分组并覆盖完整顺序 | 中 | 使用“可见子集重排、不可见项保留”的合并算法 |
| 不同页面显示不同顺序 | 中低 | 移动端所有用户可见分组入口统一读取同一 Store |
| 长按手势不易发现 | 中低 | 延续现有站点条目长按排序心智；增加可访问描述；增强版可增加显式排序入口 |
| 电视端遥控器无法使用触摸拖动 | 中 | MVP 明确只做移动端；电视端后续采用独立排序弹窗或左右移动操作 |

## 11. 排期建议

建议进入需求池，优先级设为 **P2 / 中优先级体验优化**：

- 若实际用户经常出现 5 个以上分组、标签行需要横向滑动，可提升到近期版本；
- 若大多数配置只有 2～3 个分组，则可放在站点选择体验优化批次一起做；
- 不建议为赶进度采用“站点顺序隐式决定分组顺序”或手写 `HorizontalScrollView` 拖动，这两种方案会用较低初始成本换来更高的交互和维护成本。

最终建议：**接受需求；移动端先做标签长按左右拖动；排序按配置本地持久化，并同步用于移动端其他分组展示入口；电视端排序单独排期。**


## 12. 实施状态（2026-08-10）

本次实现已从原评估中的“仅移动端 MVP”扩展为移动端与 TV 端共用同一套按 VOD 配置保存的分组顺序：

- 移动端：分组标签支持长按横向拖动，松手后保存；搜索范围与聚合页读取同一顺序。
- TV 端：在站点弹窗的分组标签上长按确定键进入排序模式，左右键移动，确定键保存，返回键取消；排序模式提供可见提示、活动标签标记和无障碍描述。
- TV 搜索范围菜单与聚合结果页读取同一顺序。
- 共享存储：使用 `site_group_order_<cid>`；新增/失效分组与屏蔽模式下的可见子集均由 `SiteGroupOrderStore` 合并处理。
- 自动验证：`SiteGroupOrderStoreTest` 在 Mobile/Leanback ARM64 Debug 变体各 7 项通过，Leanback ARM64 Debug APK 构建通过。
- 待补验证：当前连接的模拟器均被其他会话占用，未覆盖独占 TV 设备上的完整遥控器实机回归；发布前仍应按 8.2 节执行。
