## 3. WebHome 与 reader：**浅/深一致不通过**（WebHome），reader 未取证

> **§3.1 的原始结论已撤回。** 首轮据「声明了 `--webhtv-*`」判定「没有死 token」，
> 第二轮实测证明**恰恰相反**：这些声明是空壳，页面样式一次也不消费它们（§3.2.3）。
> 原文保留在下方并标注更正，以免掩盖错误。

### 3.1（已撤回）原文主张「没有只声明不消费的死 token」

原文依据：

```
eclipse.html        : 0 个硬编码 --webhtv-* hex
eclipse-detail.html : 0 个硬编码 --webhtv-* hex
reader.html         : 0 个硬编码 --webhtv-* hex
```

并称「它们把 `--webhtv-*` 当作与原生桥的接口变量，再映射到自己的样式变量」，
因此「**没有**『只声明不消费』的死 token」。

**更正**：该推理只检查了「是否声明」，没有检查「是否消费」。
实测 `eclipse.html` / `eclipse-detail.html` 的 `var(--webhtv-*)` 消费次数均为 **0**，
页面样式全部消费本地族（`--eclipse-*` 76 次 / `--eclipse-detail-*` 127 次）。
**这正是「只声明不消费」** —— 原文结论应改为「存在死 token」，见 §3.3.3。

原文给出的映射方向也写反了。实际是「本地色 → 填进 `--webhtv-*` 名」：

```
eclipse.html:156   --webhtv-primary: var(--eclipse-color-1);     ← 用本地色填 webhtv 名
```

而不是原文所设想的「原生写入 `--webhtv-*` → 页面映射到本地变量 → 样式消费」。

（设置 → 增强功能 → 全局 WebHome 皮肤 → `Eclipse（内置）`）在设备上取到了渲染证据。

#### 3.2.2 决定性 A/B：两态逐像素相同

设备侧把应用渲染模式在**同一台设备、同一份 APK、同一份源**上切换：

| 组 | `theme_mode` | 应用真实模式 | 证据 |
|---|---|---|---|
| A | `1`（深色） | dark | `E-W-17-webhome-home.png` |
| B | `0`（浅色） | light | `E-W-24-webhome-lightmode.png` |

（`theme_mode` 语义：`ThemeController.applyNightModeToApp()` 里 `0 -> MODE_NIGHT_NO`、
`1 -> MODE_NIGHT_YES`、`-1 -> 跟随系统`。**注意这与系统 `settings secure ui_night_mode`
的 1/2 语义不同**，`MATRIX-B-M-D-20261013.md` §1.1 记的是后者。）

对两图内容区（y=300..1800，每 4 像素采样）逐像素比较：

```
mean |ΔRGB| = 0.01  (满量程 765)   samples = 101250   max = 3
```

**即两态渲染结果实质逐像素相同**，WebHome 完全没有跟随应用浅色模式。

#### 3.2.3 根因：token 映射方向反了，且页面没有浅色表

`eclipse.html` 与 `eclipse-detail.html` 各声明 20 个 `--webhtv-*`，但**全部是「用本地色填 webhtv 名」**：

```
eclipse.html:156   --webhtv-primary: var(--eclipse-color-1);
eclipse.html:158   --webhtv-surface: var(--eclipse-color-3);
eclipse-detail.html:225  --webhtv-primary: var(--eclipse-detail-color-1);
```

而页面自身样式**一次也不消费** `--webhtv-*`，全部消费本地族：

| 文件 | 声明 `--webhtv-*` | 消费 `var(--webhtv-*)` | 消费本地族 | `prefers-color-scheme` |
|---|---|---|---|---|
| `webhome/eclipse.html` | 20 | **0** | 76（`--eclipse-*`） | **0** |
| `webhome/eclipse-detail.html` | 20 | **0** | 127（`--eclipse-detail-*`） | **0** |
| `reader.html` | 33 | **0** | 84（`--reader-*`） | **1** ✔ |

同时：

- 两个 Eclipse 页面**只有一个 `:root` 调色板**（`--eclipse-color-1..56`），
  值全是深色（如 `--eclipse-color-3: #101418`、`--eclipse-color-18: #080b15`），
  **没有第二套浅色值**，也没有 `@media (prefers-color-scheme: …)`；
- 页面不 `@import` / `<link>` `assets/css/ui.css`，因此拿不到共享 token 表；
- 原生桥确实注入了 token（`HomeWebController` 的 `root.add("tokens", …)` +
  `ThemeWebBridge.snapshotJson`，页面 `applyNativeTokens()` 把 `tokens.*` 写到
  `root.style` 的 `--webhtv-*` 上），但**写进去的值没有任何页面样式读取**，
  所以对渲染零影响。

`reader.html` 是**正确写法**的对照：它有 `@media (prefers-color-scheme: dark)` 第二套
映射（`--webhtv-primary: var(--reader-color-15)` 等），所以能跟随模式。

#### 3.2.4 与设计文档要求的偏差

设计文档 §18.6 阶段 E 规则 2/4 明确要求：

```
line 1219  管理页删除 body.manage-page 蓝色覆盖，改为共享 --webhtv-primary；
           WebHome 删除绿色专属 palette，改为共享 token。
line 1221  prefers-color-scheme 与 data-theme 只切换变量；
           data-theme-source 区分 native 注入和页面本地。
line 1228  管理页、WebHome、reader 三个页面截图对比一致（阶段 E DoD）。
```

现状是：WebHome 保留了**专属 palette**（`--eclipse-color-*`），`--webhtv-*` 只是空壳别名，
且没有 `prefers-color-scheme` 分支 —— 与规则 2/4 和 DoD 第 3 条都不符。

> 注：`scripts/check_ui_tokens.sh --stage E` 报 `violations=0` 是**真的**——
> 该检查器只校验「allowlist 外无原始 hex」，而 `eclipse.html` 的 hex 全在
> `:root` 的 `--eclipse-color-*` 声明里（以 `--` 开头，被规则放行），
> 且 allowlist 里已登记 `app/src/main/assets/webhome/eclipse.html`。
> **即门禁通过不代表 token 接线正确**，这是本行暴露出的门禁盲区。

### 3.3 reader：静态结构正确，设备渲染仍未取证

`reader.html` 与 Eclipse 的**结构不同且正确**：它有 `@media (prefers-color-scheme: dark)`
第二套 `--webhtv-*` 映射（line 129-145），浅色为默认。

设备渲染仍未取证：`reader.html` 由 `WebReaderActivity` 在 `novel://` 路由时加载
（`NovelRouter`），而 5560 的配置源没有小说/漫画站点，`shared_prefs` 里也没有
`novel*`/`comic*` 键。**记为未取证**（不是不通过）。

## 6. 局限

1. 管理页的渲染是在 **PC 的无头 Chrome** 里做的（该页本就是给外部浏览器用的），
   不是在设备 WebView 里渲染的。
2. 管理页渲染时页面处于「页面已关闭」变暗态，故未用像素比对 token（§2.2 注）。
3. reader 只做了静态结构验证，未取设备渲染证据（§3.3）；当前源无小说/漫画站点。
4. WebHome 的 A/B 只覆盖了**应用内**浅/深切换（`theme_mode` 0 vs 1）。
   未覆盖系统夜间位切换、也未覆盖 `theme_profile_v2` 自定义调色板叠加的场景。
5. WebHome 的取证是在 **mobile** flavor 上做的；leanback 侧未复验
   （Eclipse 的 `theme.json` 声明 `targets: ["mobile","leanback"]`）。
6. 未验证 TV（leanback）侧的 WebView 表现。
7. §3.3 的结论是「页面不消费原生 token」，**不是**「原生桥没注入 token」——
   两者已分别核实（桥注入见 §3.2.3 第 3 条）。
