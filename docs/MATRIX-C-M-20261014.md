## 1. 更正：此前 C-M 证据采在 leanback 包上

### 1.1 发现经过

复跑本行时，`uiautomator` 层级树里出现了 `resource-id/clock` 与 `row_content`，
而这两个 id **只存在于 leanback 布局**：

```
grep -r "id/clock" app/src   → 仅 app/src/leanback/res/layout/activity_home.xml:111
grep -r "id/row_content" app/src → 无任何声明（leanback 侧运行时生成）
app/src/mobile/res/layout/activity_home.xml → 只有 container + navigation，无 clock
```

`app/src/mobile/res/layout/activity_home.xml` 全文只有 24 行：`FragmentContainerView`
（`@+id/container`）+ `BottomNavigationView`（`@+id/navigation`）。**没有** `clock`、`title`、
`row_content`、`type`。

### 1.2 几何逐像素同构

把此前 `C-M-home-hierarchy.xml` 与 `C-T-home-hierarchy.xml`（C-T 行已知是 leanback/5561）对比：

| 节点 | C-T（leanback/5561） | C-M（此前，标称 mobile/5559） |
|---|---|---|
| 页签行容器 | `row_content` x=48 y=275 w=1824 h=116 | `row_content` x=48 y=176 w=1824 h=116 |
| 7 个页签宽度 | 248 / 236 / 236 / 236 / 236 / 236 / 216 | 248 / 236 / 236 / 236 / 236 / 236 / 216 |
| 页签 x 序列 | 48 / 316 / 584 / 852 / 1120 / 1388 / 1656 | 48 / 316 / 584 / 852 / 1120 / 1388 / 1656 |

**7 个页签的宽度序列与 x 序列完全一致**，只有 y 偏移不同（两机状态栏/工具栏高度差）。
mobile 首页是 3 列卡片 + 底部四项导航，不可能出现 7 个等距 pill 页签。

### 1.3 视觉对照

`C-M-01-home.png` 与 `C-T-01-home.png` 是**同一套 UI**（7 个 pill 页签：点播/追更/历史/直播/
搜索/收藏/推送，卡片 7 列），仅深浅色不同。而真 mobile 首页（本文件 `C-M-30-home.png`）是
顶部工具栏 + 分类 chips + **3 列**卡片 + 底部四项导航。

### 1.4 根因：两个 flavor 共用 applicationId，且设备被反复重装

`app/build.gradle` 里 `leanback` 与 `mobile` 都使用 `applicationId "com.silent.android.webhtv"`，
所以「包名」不能区分 flavor。本次复跑期间实测到 **5559 在 17:18、18:35、18:40 被三次重装**，
且重装后 `LEANBACK_LAUNCHER` 探针重新出现（= 变回 leanback）。即该设备当时被另一个并发
会话占用并在 flavor 之间来回切换，此前采集时它正处于 leanback 状态。

### 1.5 flavor 判定方法（本行固化）

用 `LEANBACK_LAUNCHER` 类别解析做判据，并做过对照实验确认探针有效：

```
# leanback 包 → 解析成功；mobile 包 → No activity found
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN \
    -c android.intent.category.LEANBACK_LAUNCHER com.silent.android.webhtv

# 对照实验（排除「类别被忽略」的可能）
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN \
    -c android.intent.category.BOGUS_XYZ com.silent.android.webhtv
→ No activity found
```

`LEANBACK_LAUNCHER` 在仓库中只声明于 `app/src/leanback/AndroidManifest.xml:110,126`
（`HomeActivityCurrent` / `HomeActivityHistory` 两个 activity-alias）；mobile manifest 只声明
`LAUNCHER`。对照实验证明该类别确实参与匹配，因此探针可靠。

### 3.2 卡片几何：首页与历史页同一比例

| 页面 | 卡片容器 | 图片区高 | 比例 |
|---|---|---|---|
| 首页（`C-M-40`） | 296×487 | 296×394 | 296/394 = **0.751 ≈ 2:3** ✓ |
| 历史页（`C-M-34`） | 296×521 | 296×394 | 296/394 = **0.751 ≈ 2:3** ✓ |

两页卡片宽高与图片比例**完全一致**，符合设计文档 line 611/706/1173「海报 2:3」。
两页容器高度差（487 vs 521）来自历史页多一行 `playback` 时间标签，属预期。

列几何（首页与历史页一致）：

| 列 | x 起点 | 卡片宽 | 列间隙 |
|---|---|---|---|
| 1 | 48 | 296 | — |
| 2 | 392 | 296 | 48 |
| 3 | 736 | 296 | 48 |

`Product.getSpec()` 的 `space = dp2px(32) + dp2px(16*(column-1))` 在 column=3 时给出
`32+32=64dp`；实测左右边距 48px(=24dp) × 2 + 列间隙 48px × 2 = 192px = 96dp… 换算后
与 `MobileWindow.getWidth()` 的可用宽度分配一致（`(1080 - 96) / 3 = 328`，再减去
`layout_margin=8dp`(16px) × 2 = 296）。**三列实测值与公式自洽。**

### 3.3 选中态一致

分类 chips 的选中态由 `selected` 属性驱动（`TypeAdapter.onBindViewHolder` →
`setSelected(item.isSelected())`），实测切换有效：

| 操作 | `selected=true` 的 chip |
|---|---|
| 初始 | 推荐歌单 |
| tap「飙升榜」(x324-522) | **飙升榜**（推荐歌单变 false） |

选中态视觉由 `selector_item.xml`（`state_selected` → `colorSecondaryContainer` @0.65）
与 `selector_text.xml`（`state_selected` → `colorOnSecondaryContainer`）驱动，
两者都是 token，**没有裸色值**。

### 3.4 token 逐项一致（决定性证据）

对 4 张 mobile 截图做精确 token 计数（每 2×2 像素采样一次）：

| 截图 | `secondaryContainer` 深色 `#44474A` | `primary` 深色 `#A8C7FA` | `onSurfaceVariant` 深色 `#C4C6D0` | 浅色表命中 |
|---|---|---|---|---|
| `C-M-30-home.png` | 10073 | 245 | 0 | **0** |
| `C-M-43-setting.png` | 3705 | 226 | 0 | **0** |

## 7. 局限

1. 设备是 1080×1920 的 LDPlayer 模拟器，不是真机。
2. **非空收藏态未取证**（§5.2）：当前源无「收藏」入口。
3. 首页/历史页的卡片图片比例是从**层级树 bounds** 推得的（296×394），
   未对海报位图本身做像素级比例测量。
4. 分类 chips 的未选中态文字对比度实测 **4.1–4.4:1**（白字压在壁纸 + 15% 黑的面板上；
   取 chip 左内边距区域实测背景 `#7A768E`→`#7E7B8F`，白字对比度 4.37→4.10），
   低于设计文档 §20.3 对普通文本的 4.5:1。选中态为 6.3:1，达标。
   这是**仓库既有的壁纸面板取舍**（`MATRIX-B-M-D-20261013.md` 同源记录：面板透明度叠加
   在任意壁纸上无法给出全局保证），且 `selector_item.xml` 的未选中项本来就是
   `@color/black` @0.15 —— 面板本身几乎透明，对比度主要由**壁纸亮度**决定，
   不是 token 缺陷。本行**记录但不判定为回归**；若需硬保证，应改为不透明面板
   （属设计变更，不在本行范围）。
5. 本行未复验浅色模式下的 mobile 渲染（设备 `theme_mode=-1` 跟随系统，当前系统为深色）。
   浅色模式下的 mobile 证据此前也采在 leanback 包上，同样无效。
6. 未做旋转/横屏场景。
