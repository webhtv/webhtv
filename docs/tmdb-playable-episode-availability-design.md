# TMDB 详情页可播放季度与选集设计

- 状态：Implemented
- 日期：2026-07-31
- 适用范围：原生增强、沉浸融合、炫彩详情、详情直放
- 关联代码：`EpisodeSeasonPolicy`、`TmdbDetailActivity`、`VideoActivity`、`TmdbUIAdapter`

## 1. 背景与问题

TMDB 详情数据描述作品的完整季度和集数，但当前播放线路（`Flag`）可能只包含：

- 某一个季度；
- 某一季度的部分集数；
- 单独一集；
- 无法可靠识别季度的扁平集数列表。

现有 `TmdbDetailActivity` 将 `TmdbBundle.seasons()` 写入 `seasonNumbers`，并直接用它渲染季度按钮；随后才使用当前线路的 `Episode` 列表筛选内容。这会产生以下问题：

1. 显示当前线路并不具备的季度；
2. 点击季度后得到空列表，或多个季度重复显示同一批线路集数；
3. TMDB 元数据被误当成可播放数据；
4. 遥控器和触屏用户需要经过无效导航项。

原生增强模式的 `VideoActivity` 当前直接渲染 `Flag.getEpisodes()`，TMDB 只向这些对象补充标题、剧照等元数据；该模式已经符合“线路为播放事实源”的基本原则，需要保留这一行为并防止回归。

## 2. 设计决策

### 2.1 核心原则

> 选集区域只展示当前线路真实存在的 `Episode`；TMDB 只负责丰富这些播放项，不创建播放项。

将季度拆成两个概念：

- **元数据季度（metadata seasons）**：TMDB 返回的完整季度，用于标题、剧照、播出日期、集数位置等匹配；
- **可播放季度（available seasons）**：根据当前 `Flag.getEpisodes()` 能可靠确认的季度，只用于季度导航和选集过滤。

两者不能共用同一套 UI 语义。

### 2.2 安全退化原则

- 能可靠分季：只显示确认可播放的季度，并过滤到该季度真实存在的线路集数；
- 不能可靠分季：隐藏季度导航，原样显示当前线路全部集数；
- 唯一季度可可靠确认时，只隐藏无意义的切换导航，不隐藏季度语义；顶部元信息和选集标题必须显示当前季；
- 不允许因为 TMDB 存在某集，就生成没有线路 URL 的选集卡片；
- 不允许因为部分线路集数无法识别季度，就静默丢弃这些播放项。

“无法判断”必须退化为扁平列表，不能等同于“第一季”，也不能等同于“所有季度”。现有兼容性单季判断只允许用于隐藏季度导航和选择 TMDB 元数据季，不得扩展线路播放项。

## 3. 可播放季度解析顺序

解析函数接收：

- 当前线路集数数量；
- 每个线路集数解析得到的季度号（`0` 为特别篇，未知为 `-1`）；
- 标题中解析得到的季度号；
- TMDB 第一有效季度；
- TMDB 完整季度及各季集数。

按以下优先级解析：

1. **显式季度号优先**
   - 只有当每个线路集数都能解析出季度，且所有季度都存在于 TMDB 季度集合中时，才按显式季度分组；
   - 季度导航只显示线路实际出现过的季度；
   - 若显式季度只覆盖部分集数，或任一季度不属于当前 TMDB 匹配结果，立即退化为不分季，避免丢集或绑定错误季度。

2. **标题明确包含季度**
   - 仅在线路集数完全没有显式季度号时，才使用线路标签、片名或源标题中的“第 X 季 / Season X / Sxx”；
   - 标题季度必须存在于 TMDB 季度集合中，否则退化为不分季；
   - 成功时将整条线路视为该季度，只绑定该季度元数据。

3. **单一 TMDB 季度**
   - 仅在线路集数和标题都没有季度信号时，TMDB 的唯一季度才作为元数据季；
   - UI 不显示季度导航。

4. **线路总集数精确覆盖 TMDB 全季集数**
   - 仅当 `EpisodeSeasonPolicy.canSliceBySeasonCounts(...)` 为真，即每季集数完整且总和与线路集数完全相等时，才允许按 TMDB 季集数顺序切分；
   - 此时显示全部能够映射的季度。

5. **既有单季兼容策略**
   - 保留 `shouldUseSingleSeasonEpisodeData(...)` 的既有兼容场景；
   - 返回单一季度并隐藏季度导航；
   - 该策略不增加、不删除线路集数。

6. **无法可靠映射**
   - 返回空的可播放季度集合；
   - `selectedSeasonNumber = -1`；
   - 隐藏季度导航并展示线路原始列表。

## 4. UI 行为矩阵

| 当前线路 | 可播放季度导航 | 选集内容 |
|---|---|---|
| 仅 `S03E05` | 隐藏切换导航，显示“第 3 季”上下文 | 仅 `S03E05` |
| 第 2 季 E01-E08 | 隐藏切换导航，显示“第 2 季”上下文 | 8 个真实播放项 |
| 明确包含第 1、3 季 | 只显示第 1、3 季 | 每季仅显示对应线路集数 |
| E01、E02、E04 | 隐藏或显示所属唯一季度 | 只显示 1、2、4，不补 E03 |
| 无季度信息的 8 集扁平列表 | 隐藏 | 原样显示 8 集 |
| 线路数量精确等于 TMDB 多季总数 | 显示可映射全部季度 | 按 TMDB 季集数精确切片 |
| 部分集有季度、部分未知 | 隐藏 | 原样显示全部线路集数，避免丢集 |

本阶段不增加灰色禁用季度，也不增加自动换源。未来如需提供完整作品季度感知，应采用“其他季度需换源/搜索”的独立入口，不应把不可播放季度放进选集导航。

## 5. 状态与切换规则

### 5.1 初次进入

1. 从历史记录或默认规则选择 `selectedEpisode`；
2. 根据当前线路解析可播放季度；
3. 若能映射，选择当前集所属季度或唯一季度；
4. 若不能映射，季度设为未知并展示扁平列表；
5. 只为当前映射季度获取和绑定 TMDB 集信息。

### 5.2 切换线路

切换 `Flag` 后必须：

- 清空当前季度和可见集数缓存；
- 重新解析新线路的可播放季度；
- 优先恢复新线路中与历史记录或当前播放位置匹配的集数；
- 当前集不存在时，退回新线路第一项；
- 不保留旧线路中已经不可用的季度按钮。

### 5.3 切换季度

- 季度按钮只可能来自可播放季度集合，因此点击后必须至少存在一个线路播放项；
- 切换后选中该季度第一项，并按需加载该季度 TMDB 元数据；
- 不允许出现“季度按钮可点但列表为空”的稳定状态。

## 6. 代码结构

### 6.1 `EpisodeSeasonPolicy`

新增纯函数 `resolveAvailableSeasons(...)`：

- 不依赖 Android UI；
- 不修改输入集合；
- 返回不可变季度列表；
- 集中承载上述解析优先级，便于单元测试；
- 继续复用现有 `canSliceBySeasonCounts(...)` 和 `shouldUseSingleSeasonEpisodeData(...)`。

### 6.2 `TmdbDetailActivity`

- `seasonNumbers` 保留为 TMDB 元数据季度；
- 新增当前线路可播放季度解析方法；
- `renderSeasonSelection()`、`updateSeasonButtonStates()`、季度焦点定位改用可播放季度；
- `computeVisibleEpisodes()` 只有在映射可靠且存在多个可播放季度时才过滤/切片；
- `seasonForEpisode()` 不能再回退到与线路无关的 TMDB 第一季；
- 换线、TMDB 数据变化和剧集重渲染时重新计算，不保存跨线路的可播放季度状态。

### 6.3 `VideoActivity` / 原生增强

- 继续把 `Flag.getEpisodes()` 直接传给选集适配器；
- `TmdbUIAdapter` 只能修改现有 `Episode` 的元数据字段，不得替换为 TMDB 全量剧集；
- 本次以回归验证为主，不引入第二套季度导航逻辑。

## 8. 非目标

本次不处理：

- 自动搜索或自动切换到拥有其他季度的线路；
- 聚合多条线路形成跨线路完整季度；
- 为缺失集数生成禁用占位卡；
- 修改 TMDB API、缓存协议或站源解析协议；
- 重构整个 `TmdbDetailActivity` 剧集 Delegate。

## 9. 验收标准

- 当前线路只有一集时，选集区只出现这一集；
- 当前线路只有某一季时，不出现其他 TMDB 季度；
- 当前线路只有某一季时，顶部元信息和选集标题仍明确显示该季；
- 当前线路有多个明确季度时，只出现这些季度；
- 无法可靠分季时，不丢失任何线路播放项；
- 所有季度按钮点击后都有至少一个可播放项；
- 换源后季度导航立即依据新线路重算；
- 原生增强仍只展示当前线路集数；
- 既有季度切片、集号、历史恢复与播放测试无回归。

## 10. 实施结果

## 11. 原生增强补充：季度上下文与播放历史隔离

后续在 `VideoActivity`（原生增强）验证时发现两个关联问题：

1. TMDB 刮削会把原始线路标题替换成标准剧名；如果原始标题中的“第 2 季 / Season 2 / S02 / 尾缀 2”未在替换前保存，选集区只显示“选集”，用户无法确认当前线路属于哪一季；
2. 同一 TMDB 剧集的多季线路会参与聚合历史匹配。当前线路剧集尚未完成 TMDB 异步绑定时，仅按“第 5 集”等原始集号匹配，可能把第一季第 5 集的进度复制到第二季第 5 集。

### 11.1 原生增强的季度来源

`VideoActivity` 与 `TmdbUIAdapter` 必须在任何 TMDB 标题覆盖之前捕获来源季度。可靠性顺序为：

1. 详情直放传入的明确 TMDB 季号；
2. 当前线路原始剧名、入口原始剧名和线路标签中的显式季度；
3. 当前线路已绑定剧集上的一致 TMDB 季号；
4. 无可靠季度时保持未知，不默认在界面上显示“第 1 季”。

原生增强仍只展示 `Flag.getEpisodes()` 中真实可播放的项目，不生成 TMDB 全量占位集。可靠季度存在时：

- 选集标题显示“选集 · 第 X 季”；
- 移动端融合头部补充“第 X 季”只读元信息；
- `TmdbUIAdapter` 仅请求该季的 TMDB 剧集标题；明确请求第 X 季失败时不得回退并套用第 1 季标题；只有来源季度未知时才保留原有“第 1 季 → 特别篇”的兼容探测。

### 11.2 历史与缓存身份

剧集续播身份必须至少包含：

```text
(mediaType, tmdbId, seasonNumber, episodeNumber)
```

当目标来源季度已知时：

- 已知季号且与目标季不同的聚合历史一律拒绝；
- 季号未知的旧历史只允许在完全相同的来源 `key` 内兼容恢复，不允许跨来源猜测共享；
- 同一 TMDB、同一季、同一集可继续跨来源共享进度；
- 当前播放历史在保存前补齐来源季号和集号，即使 TMDB 异步标题尚未返回；
- 单集位置缓存键加入季号前缀，避免同一来源/线路中 `S01E05` 与 `S02E05` 使用相同的原始集名而串进度。

该规则同时应用于原生增强 `VideoActivity` 和三个 TMDB 独立详情模式，保证入口不同但续播语义一致。

### 11.3 新增验收项

- 原生增强打开“第 2 季”线路时，选集标题明确显示“第 2 季”；
- 原始标题含季度、TMDB 标准标题不含季度时，刮削后仍保留季度上下文；
- 第一季第 5 集有进度时，进入第二季第 5 集不得继承第一季进度；
- 返回第一季第 5 集仍可恢复第一季自己的进度；
- 同一季同一集切换来源时，在开启聚合的既有语义下仍可共享进度；
- 明确第 2 季的 TMDB 标题请求失败时，不得用第 1 季标题覆盖当前线路集名。
