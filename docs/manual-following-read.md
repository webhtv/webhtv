# 追更手动已读改造记录

## 目标

- 追更列表不再因为卡片进入可视区域而自动标记已读。
- 每条未读追更只能通过“标记已读”手动确认；点击卡片查看详情不改变已读状态。
- 顶部提供“全部已读”，一次性确认当前列表中的全部未读消息。
- 保持顶部操作区紧凑，中文文案明确区分“标记已读”和“全部已读”。

## 实施记录

- 移除 `FollowingActivity` 的滚动停顿监听、800ms 延迟任务和可视区域批量写入逻辑。
- 保留每张卡片上的显式“标记已读”按钮，并收窄按钮内距，避免横向操作区过度占宽。
- 新增顶部“全部已读”按钮；只收集当前列表中 `hasUpdate` 的条目，避免把已读条目重复写入数据库。
- 同步适配 leanback 与 mobile 顶部操作布局，确保 ViewBinding 在两个模式下都能生成 `readAll` 操作。
- 已读写入仍在后台线程完成，本地先即时清角标，成功后刷新未读数，失败时回读数据库恢复真实状态。

## 验证

- 目标验证：`./gradlew :app:testMobileArm64_v8aDebugUnitTest --tests 'com.fongmi.android.tv.ui.activity.FollowingUiSourceTest'`。
- 现有 `FollowingUiSourceTest` 中关于可视区域自动已读的旧断言需同步改为“不存在”，否则会阻止本需求验收。

## 回滚

- 本任务只涉及追更列表交互；如需回滚，还原本任务提交即可恢复原有数据结构，不涉及数据库迁移。
